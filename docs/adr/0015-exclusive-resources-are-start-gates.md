# 0015. 独占资源是启动前的门，不是长租约

## 状态

已采纳，2026-10-24。澄清 0011 与 0009 之间关于"独占资源"生命周期矛盾。

## 决策

**独占资源只控制"节点能否启动"，不授予文件写权限。**

节点在配置里声明它独占哪些资源（目录树、锁文件、端口、数据库、构建缓存）。同一资源在同一
时刻只允许一个节点处于运行状态：第二个节点**排队等待**，前一个节点结束后自动放行。

**它不产生长租约。** 节点内每次写入仍然各取一张单次租约（0009）。"一次工具调用一张租约"
这条不变量不因独占资源而出现例外。节点级的长租约仍被否决，理由不变：崩溃后工作区会被锁到
TTL 到期，而收益可以由这道门提供。

**这道门由 server 仲裁**，因为同一资源可能被不同工作区的节点声明（构建缓存、端口）。门的
归属记录带 TTL 与心跳，节点崩溃后按 TTL 释放，不依赖进程正常退出。

**写集重叠本身不阻塞启动。** 两个节点都声明写同一批文件时，它们仍可并发启动、并发读、并发
推理，只在第一次真正获取写租约时排队。这条保留了并行度：工作流里节点的绝大部分时间花在
推理上，而不是写文件。

**静态检查的动作要分清三类情况：**

| 情况 | 动作 |
|---|---|
| 独占资源被两个节点声明 | 排队（运行期由门保证顺序），不阻止载入 |
| 写集重叠但未声明独占 | 允许并发，写在租约排队，载入时只提示 |
| 环依赖、读一个由别人删的路径、目录与文件粒度混用 | 拒绝载入（无法通过排队解决） |

第三种之所以拒绝载入，是因为它们在任何执行顺序下都不成立，让工作流跑起来再失败只会浪费
一次完整运行。

**子节点继承父节点的独占声明**，且继承的是交集：父声明独占目录树时，子节点无法通过声明
更细的路径绕开它。

## 理由

w1mer 的"编译独占"是这套设计的来源，但它的真实需求是**"别在我构建期间改我的文件"**，而不是
"整个节点期间锁住工作区"。这道门恰好满足前者：构建发生在某个节点运行期间，而该节点已经
独占了构建相关资源。

选门而不是长租约，是因为门可以排队而租约不能——租约被占时调用会失败返回（0009 的语义是
"拒绝并告知持有者"），而节点启动失败意味着整段工作流停摆。排队对节点启动是合适的语义，
对工具调用不是。

写集重叠不阻塞启动，是因为阻塞会牺牲无需牺牲的并行度。两个节点都在读同一批文件做分析时，
没有任何理由让其中一个等另一个。

## 后果

好的方面：编译独占有确定实现；不引入长租约；并行度保留；崩溃可回收。

代价：

- **排队会让工作流的墙钟时间不可预测**：某个节点跑得久，后面排队的全部顺延。因此需要把
  排队状态推送到界面，否则用户会以为卡住了。
- **门与租约是两套机制**，实现与文档都要分清；混淆会让"节点为什么没启动"和"工具为什么
  被拒"两种错误混在一起。
- **跨工作区的资源声明需要全局注册表**，这是 server 已有的职责，但资源命名的规范化要做
  （同一个目录的不同写法要归一到同一资源键）。

需要重新审视的信号：如果排队成为工作流的常态瓶颈（例如多个节点都声明同一个构建缓存），
说明资源粒度太粗，应改用更细的声明，而不是把门换成租约。

## 被否决的替代方案

**节点级长租约（整个节点期间独占）。** 语义最接近"独占"的字面意思。不选的理由是崩溃后
锁到 TTL 到期、需要心跳维持，且它与"一次工具调用一张租约"的不变量并存时需要解释两套生命
周期。门已经满足需求。

**写集重叠即拒绝载入。** 最安全。不选的理由是它把大量本可并行的节点串行化，而写冲突本来
已经由租约处理。

**写集重叠即排队（不区分独占声明）。** 实现统一，行为简单。不选的理由是它会让所有写同一
模块的探索型节点互相阻塞，而那些节点大部分时间在推理。

**只在节点内部串行（不允许工作流内并发）。** 最简单。不选的理由是它放弃并行探索，而并行
探索是长程任务缩短墙钟时间的主要手段。
