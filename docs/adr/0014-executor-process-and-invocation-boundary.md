# 0014. 执行器是独立进程，一次调用有明确边界

## 状态

已采纳，2026-10-24。澄清 0001 与 0013 之间关于执行器归属的矛盾。

## 决策

**执行器是每个工作区一个独立进程**，不是 server 内部的一个 unit。

0013 的最小拓扑里那个叫 `executor` 的 unit 更名为**租约仲裁**，职责收窄为两件事：维护
租约表、仲裁跨工作区的全局资源（端口、构建缓存）。它不执行工具、不创建沙箱子进程、
不持有工作区文件句柄。工具执行全部发生在每工作区的执行器进程里。

之所以必须分开，是因为 0001 给出的理由仍然成立且不可让：工具是第三方二进制，如果它与
持有数据库与凭据的进程在同一信任域，它就能直接改写主数据目录。把执行器并进 server 会让
这条理由失效，代价远大于收益。

**一次工具调用的边界由执行器划定。** 组 = 执行器为这次调用创建的全部后代进程，包括沙箱
监督进程、工具模板、工具二进制、管道各段、以及嵌套调用的每一层。执行器是唯一的组长。

**快照在整组退出并被回收之后才打。** 不是"工具二进制退出后"，也不是"模板返回后"——
后台子进程（格式化器、监听器、测试运行器的子进程）会在上游退出后继续写文件，提前打点会
把半写状态固化成可回滚的历史。

**模板以监督进程方式运行，不使用 `execve` 替换自身。** 因为它既要启动真正的二进制，又要
把结果与退出码回传。因此父进程链是：执行器 → 沙箱监督 → 模板 → 工具二进制，比"工具二进制
是沙箱子进程"这句话描述的深一层。回收必须逐层等待，不能只等第一层退出。

**跨平台的组表达。** POSIX 上用进程组加会话，并让执行器成为子进程收割者（subreaper），
否则模板或工具自行 daemon 化后，孙进程会被 init 收养而逃出回收范围。Windows 上用作业对象
（Job Object），它的语义本身就包含"关闭句柄即回收全树"。

**嵌套调用的通道与继承键。** 沙箱内通过 `PATH` 注入的 shim 被调用时，它把请求连同**外层
调用标识**（环境变量传入，执行器用连接凭据核验）回传给执行器。执行器据此找到外层租约，
只允许在该租约的路径集合内派生子命令，不授予新路径、不新建第二张租约。因此嵌套调用在一次
调用内仍然只有一张租约、一份快照。

**崩溃降级。** server 不可用时 worker 进入只读暂停：显示层可以继续渲染已缓存的内容，任何
写操作与模型调用都返回明确的"暂不可用"，不排队、不本地落盘。执行器崩溃时其租约按 TTL 过期，
工作区恢复可写。

## 理由

把执行器放在 server 内能省掉一层 IPC，但它把"工具不能碰到主数据目录"这条唯一不可让的隔离
换掉了一层性能。本项目对安全边界的立场是"宁可多一次跨进程调用"，因为工具的来源不可控。

组边界必须由执行器定义，而不是由工具或模板自报：模板是第三方代码（固然受固定 ABI 约束），
但把"是否已全部回收"的判断交给它，等于把快照正确性交给信任链最外圈。

嵌套调用必须有通道，否则 `PATH` 注入就只是装饰——而 `PATH` 注入是"复杂文法交给真实 bash，
但工具调用仍然过执行器"这个设计成立的前提。

## 后果

好的方面：快照时机的判据可执行；嵌套调用有明确归属；跨平台表达有对应物；崩溃语义明确。

代价：

- **执行器是一个额外的常驻进程**，每个工作区一份，空闲时仍有内存开销。可以在工作区空闲
  超时后回收，重建成本低。
- **回收要逐层等待**，一个卡住的孙进程会拖住整次调用的收尾。因此组内需要超时与强制终止，
  且强制终止本身要记录事件（否则会出现"工具报成功但快照不完整"）。
- **subreaper 是 Linux 特有设施**，其它平台要各自实现等价能力，属于 0010 的保真度矩阵。
- **server 不可用时暂停而不是排队**，用户会感到明显的功能中断。这是刻意的：排队意味着
  worker 侧要维护待写队列，那等于又开了一个真相来源。

需要重新审视的信号：如果实测发现执行器进程的空闲开销不可忽略（比如几十个工作区同时打开），
先考虑空闲回收，而不是把执行器并回 server。

## 被否决的替代方案

**执行器作为 server 内的 unit。** 省掉一层 IPC，共享连接与内存缓存，0013 原本的拓扑就是
这样画的。不选的理由是它让工具成为持库进程的子进程，0001 的信任域论证失效；且与 0002
"执行器不持有数据库连接"直接冲突。

**模板做组长，执行器只等模板退出。** 少一层等待。不选的理由是把回收正确性交给信任链最外圈，
而模板恰恰是最不希望它承担安全职责的那一层。

**禁止嵌套调用。** 只需分步执行，最简单。不选的理由是它让 `PATH` 注入失去意义，也让"复杂
文法走真实 bash"这条路径变成半残——shim 能被调用却不能工作，比不注入更糟。

**让 worker 进程兼做执行器。** 少一个进程。不选的理由是 worker 是模型循环的宿主，工具崩溃
或死循环会直接影响会话；而且 worker 未来要支持远程部署，本地进程组的语义在远端不成立。
