# 0010. 沙箱按策略与保真度建模

## 状态

已采纳，2026-10-23。

## 决策

沙箱接口只有两个操作，形状跨平台可表达，不照搬任何一个操作系统原语。

```
probe() -> Fidelity         本机在哪些维度上能强制到什么程度
apply(policy: Policy)       施加一份声明式策略
```

**Policy 是声明式模型**，与工具 manifest 里写的权限是同一份东西：路径读写范围、
网络意图（域名与端口）、可执行白名单、环境变量清洗、资源上限。

**Fidelity 是诚实的能力矩阵**，带版本号而不是布尔值。缺少必需维度时默认拒绝运行，
而不是静默降级。降级模式必须显式开启，且要在输出里标明"仅策略检查，未强制"。

**按主机限制出网在任何平台都做不到。** Linux 的 landlock 只能表达端口（且需要较新的
内核），macOS 与 Windows 也没有对应物。因此网络声明分两级：端口级（可强制）与域名级
（意图声明，实际是否强制由 Fidelity 报告）。不这么写会让工具作者误以为写了就生效。

**执行器的权限检查只是快速失败与好错误信息**，不是安全边界。安全边界在沙箱：路径必须
按真实路径解析、跟随内核的符号链接策略、由子进程继承。字符串前缀匹配会被路径穿越、
符号链接、大小写差异绕过。

**模型流量全部经 server 代理，worker 与沙箱默认无网络。** 因此最需要出网的那个组件
不在沙箱里，沙箱的默认拒绝策略得以保持极简。

**需要快照前先回收工具进程组。** 后台子进程会在工具返回后继续写文件，这与快照时机
（见 0005）共用同一套进程组设施。

## 理由

按策略而不是按系统调用建模，是因为三个平台的机制完全不同：Linux 有 landlock、
seccomp 与可选的用户命名空间；macOS 用沙箱配置文件；Windows 用 AppContainer 与作业
对象。如果接口长成 landlock 的形状，另外两个平台就只能模拟，接口会逐渐腐化成"Linux
特权接口加两个兼容层"。

Fidelity 带版本而不是布尔，是因为"支持"这个说法在旧内核上是假的：landlock 在较旧内核
上存在但没有网络维度，布尔值会把这种情况报成可用。版本号让调用方可以判断具体能力。

默认拒绝运行而不是降级，是因为权限降级是静默的安全损失。用户以为文件被限制在工作区，
实际没有——这类错误在 agent 自动运行的前提下不可接受。

## 后果

好的方面：一套声明三平台可表达；能力缺失可见；默认安全。

代价：

- **Linux 上先做，其他平台暂不可用。** 这符合当前优先级，但接口要提前定型，否则返工。
- **域名级网络策略在大多数平台只是意图。** 要真正强制需要网络命名空间加代理，属于重型
  方案，只在必要时为一类工具启用。
- **诚实报告意味着有些工具在某些平台直接不能装。** 这比"装了但权限没生效"好，但会让
  包管理器的可用性提示变复杂。

需要重新审视的信号：如果 Fidelity 报告的缺失维度集中在同一项（比如端口级网络），说明那
一项要么该做成可选代理，要么该从默认声明里去掉。

## 被否决的替代方案

**接口按 Linux 原语设计，其他平台做模拟层。** 实现最快，Linux 上能力最强。不选的理由是
模拟层会不断被绕过：一旦某个参数在 macOS 上无意义，工具作者就会开始写平台分支，最终
manifest 变成三份。

**只用策略检查，不做系统级沙箱。** 跨平台一致、实现简单。不选的理由是它把安全建立在
"路径字符串比较正确"这个假设上，而这个假设会被符号链接与路径穿越打破，且失败是静默的。

**默认降级到策略检查并告警。** 用户体验最好（到处都能装）。不选的理由是告警会被忽略，
而权限没生效的后果是工具能读写工作区以外的任意内容。

**让 worker 直接持有模型密钥、自己出网。** 省掉代理层。不选的理由是密钥会进入沙箱可达
范围，而沙箱里跑的是第三方二进制。
