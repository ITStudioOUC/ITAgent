# 0008. 只用原生工具调用

## 状态

已采纳，2026-10-23。

## 决策

只使用模型供应商提供的原生工具调用，不做正文标签解析，也不做正文 JSON 解析。

**工具定义只有一个，且永久静态。**

```json
{
  "name": "run",
  "description": "在工作区执行一条命令",
  "input_schema": {
    "type": "object",
    "properties": { "command": { "type": "string" } },
    "required": ["command"],
    "additionalProperties": false
  }
}
```

参数就是一个字符串，里面放命令（文法见 0007）。工具目录在会话开始时固定，后续新增工具
只追加一条目录事件到上下文，不改工具定义。压缩是唯一允许重建目录的时点。

**模型层做归一化，但保留原文。** 规范化层（文本、命令、结果、思考、通知）用于解析上下文
与压缩；原始层（供应商报文）用于 replay 与字节级缓存命中。两层都落库，正文以内容寻址
引用加预览的形式存储（见 0018）。

**思考块原样透传。** 带签名的思考内容必须原样回传才能续写，因此规范化层只把它当作不透明
载体加供应商标记；压缩时整段丢弃并标记失效。

**关闭并行工具调用。** 单写者工作区下并行写没有意义，显式关掉比事后串行更清楚。

**必须打开供应商的缓存机制**，并把用量字段（输入、输出、缓存读写）落事件表。

## 理由

**终止信号确定。** 原生调用给出明确的结束原因，循环状态机清晰：有调用就执行并续写，
没有就结束本轮。正文标签模式必须靠"这一轮有没有解析到命令"推断，而模型最典型的失败
就是写完命令后自行编造工具输出继续推理。原生模式下这个错误在结构上不可能发生。

**训练分布匹配。** 两大供应商的模型都在工具调用上做过训练，而"单工具、单字符串参数"
恰好是它们见过最多的形状。因此最简 schema 不是妥协而是最优形状：省掉全部逐工具定义，
而且在工具数量增长时不会降低选择准确率。

**静态工具定义是缓存的前提。** 供应商会自动缓存工具定义与前缀。一旦把检索结果塞进工具
定义，每轮前缀都变，缓存全部失效，长程任务的输入成本会成倍上升。因此检索结果只能进消息。

**删除文本模式是删掉纯复杂度。** 文本标签模式还要解决"命令怎么开始"（正文讨论命令时会
误判）、"内容里的标签怎么转义"两个问题，而它的唯一优势——供应商无关——用归一化层就能
拿到。

## 后果

好的方面：状态机干净；缓存可命中；用量可记账；工具数量增长不损害准确率。

代价：

- **支持无工具调用能力的模型需要另写一层。** 届时正确的做法是约束解码（从生成层强制
  形状）而不是正文 JSON 解析，因为后者同时继承了两边的缺点：没有终止信号，还要处理转义。
- **所有工具共用一条命令通道**，意味着工具的可发现性靠目录文本而非结构化定义描述，
  需要懒加载展开。
- **供应商差异泄漏到提示词设计。** 比如是否允许文本块跟在工具调用之后，两家行为不同。
  归一化层要抹平这一点，但抹平本身要写测试。

需要重新审视的信号：如果出现必须支持、又没有原生工具调用的模型，先看它是否支持约束
解码或 OpenAI 兼容端点，两者都比自建文本协议好。

## 被否决的替代方案

**正文里用 `<tool></tool>` 标签包裹命令。** 供应商无关，任何模型都能用。不选的理由有三
条：没有终止信号（必须靠启发式判断本轮是否结束）；标签会出现在正文里（agent 调试自己时
会讨论这个字符串，需要剔除代码围栏并规定转义）；写完命令后模型容易自行编造输出，而这个
错误在原生模式下不可能发生。

**正文里输出最小 JSON。** 这是后来提的方案，看起来折中。不选的理由是它同时继承两边的
缺点：JSON 边界要自己从正文里找（需要流式校验器，比 heredoc 的行扫描复杂得多）；内容
里的换行与引号必须转义，而 heredoc 本来就是为了免掉这一层；并且仍然没有终止信号。

**每个工具一个结构化定义（传统 function calling）。** 最"标准"的做法。不选的理由是它
让工具目录随工具数量线性膨胀，选择准确率随之下降，而且新增工具会让前缀缓存失效。单条
命令通道把这些成本一次性消掉。

**把工具检索的 top-k 结果写进工具定义。** 能提升选择准确率。不选的理由是它每轮改变前缀，
缓存全失效——省下的选择错误抵不上涨上来的输入成本。检索结果进消息即可。

**在正文里输出完整 shell 脚本并执行。** 表达能力最强。不选的理由是权限模型失效（见 0007）。
