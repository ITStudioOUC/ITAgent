# 0004. 语义压缩即折叠

## 状态

已采纳，2026-10-23。

## 决策

压缩不是"删掉旧消息"，而是"造一个帧并把 head 移到新节点"，与回退共用同一个原语
（见 0003）。做语义压缩，不是只丢旧工具输出。

**流程固定。** 在当前上下文下注入压缩指令，模型按约定格式输出摘要，成功后新建一个帧
节点、把 head 移过去，并保留最近三轮对话原文。压缩结束后上下文是：帧序列 + 最近三轮 +
末尾追加的语义摘要。

**摘要边界必须精确。** 被摘要覆盖的范围是"旧头部到最后三轮之前"，不包含保留的三轮。
否则同一件事会以摘要与原文两种版本同时存在，模型遇到矛盾时行为不可预测。

**摘要分两层。** 散文部分由模型写（做了什么、为什么这样选），事实部分由机器填：
改动文件清单与增删行数、失败过的测试、报错摘要、检查点编号、实际耗时。失败尝试与
已否决的方案必须有一节，且由机器填事实，不能靠模型回忆。

**压缩是一次事务。** 摘要生成失败、格式不合法、被输出长度截断时，不移动 head，保留
旧上下文并重试。绝不出现"上下文已清空、摘要没拿到"的中间态。

**必须预留余量。** 压缩本身要一次模型调用，输入是整个上下文。因此触发阈值是预算的
六到七成，并且在预算表里单列压缩预留。到九成才触发意味着压缩请求自己就发不出去。

**压缩调用本身要落库。** 固定提示版本、温度为零，完整请求与响应都进事件表，否则
replay 与调试都会失真。

## 理由

长程任务里上下文爆炸是主要失效模式，而"只丢旧工具输出"压不了多少：真正占空间的是
被读到的大段文件与错误信息，而它们的语义价值在于"曾经看到过什么"，不在于原文。语义
压缩才能把"探索了三小时"压成"确认了这三个事实、否决了这两条路线"。

保留最近三轮而不是"保留最近 N 千 token"：轮是一个稳定单位，而单轮大小不可控（一轮里
可能有一次两千行的文件读取）。因此保留三轮的同时，把其中工具输出的正文换成"命令 +
一行结果 + 可寻回的节点编号"，正文留在库里按需取。这既控制了预算，又没丢失可恢复性。

摘要分层是为了抑制一个已知的系统性问题：让模型总结自己，它倾向于美化，会漏掉失败尝试，
导致下一轮重复已否决的方案。机器填事实这一半不可美化，它是防止传话游戏的主要手段。

事务性是因为压缩失败的概率不低（格式错、被截断、网络断），而它恰好发生在上下文最满的
时候，此时再丢一次上下文，代价是整段任务白跑。

## 后果

好的方面：上下文预算可控；非线性开发可行（回到早期帧继续走另一条路）；压缩点成为天然
的检查点。

代价：

- **压缩是有损的，且损失不可逆。** 因此保留了按编号寻回原文的能力，把"损失"降级为
  "多一次往返"。用户与 agent 都应该知道摘要不是原文。
- **压缩作废整个前缀缓存。** 所以策略是"少次、深压缩"优于"频繁、浅压缩"，这与"尽量
  早压缩"的直觉相反，需要按六到七成阈值执行。
- **压缩本身有成本与延迟**，尤其在上下文最满的时候，一次压缩可能要几十秒。这是长程
  任务中可感知的停顿。
- **摘要质量依赖模型**，不同模型差异明显。这属于可观测项：压缩后若干轮内重复已否决
  操作的比例，是它的零成本代理指标（从真实会话离线统计，不额外调用）。

需要重新审视的信号：如果出现"压缩后反复重试同一失败方案"，先查摘要的事实层是否包含
失败记录，而不是调阈值。

## 被否决的替代方案

**滑动窗口，只丢最旧的消息。** 最简单，且无损于最近上下文。不选的理由是它放弃远期
信息：长程任务的价值恰恰在于几小时前的决定还在起作用，而滑动窗口会把"为什么这样设计"
丢掉，只留下"现在是什么样"。

**只丢旧工具输出，保留全部对话文本。** 这是很多工具的第一步压缩策略。作为压缩的第一
阶段是合理的（成本为零），但单独使用压不动：一次大文件读取的输出正文被丢掉之后，对话
里仍然留着"我读了 X"的多条来回。我们把它作为压缩前的廉价预处理，而不是压缩本身。

**按 token 数保留最近 N 个 token 的原文。** 比按轮保留更精确，但边界不稳定：同一段
对话在不同模型下切在不同位置，导致解析结果不可复现，破坏了 0003 的纯函数承诺。按轮
保留的边界是数据的属性，不是分词器的属性。

**让模型自己判断"什么时候该压缩"。** 模型对剩余预算的估计不可靠，而且它在任务中途
更倾向继续推进而不是停下来整理。阈值由内核确定性给出，帧内怎么做由 agent 决定。

**把压缩与回退做成两个不同的机制。** 看似更符合直觉（一个是清理、一个是撤销），实际
会产出两套 head 操作与两套边界条件。既然两者都是"改变 resolve 的输入"，共用原语更省。
