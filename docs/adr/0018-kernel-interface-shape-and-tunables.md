# 0018. 内核接口形状与可调参数

## 状态

已采纳，2026-10-24。填补 0003、0004、0006、0009、0011 中缺失的定义与数量参数。

## 决策

### 一、`resolve` 的输入形状

解析是纯函数，凡它需要的外部状态都必须作为参数传入。

```
ResolveInput {
  head: NodeId,
  fixed_layer: FixedLayer,        // 冻结的系统提示、工具目录快照、AGENTS.md 内容
  frames: Vec<Frame>,             // 已按时间顺序排好，含弱引用的检查点
  recent: Vec<NodeId>,            // 保留的原文轮次（默认三轮）
  checkpoint_status: Map<CheckpointId, CheckpointFacts>,
  budget: Budget,                 // 上限、压缩阈值、预览长度
}

CheckpointFacts {
  reachable: bool,                // 该检查点是否仍在快照保留窗口内
  disk_matches: bool,             // 当前磁盘哈希是否等于该检查点记录的哈希
}
```

`ResolveInput` 由 server 在调用前装好。内核只消费，不查询。

### 二、漂移状态是两个布尔量，不是三态

`reachable` 与 `disk_matches` 正交，四种组合各有一条消息：

| reachable | disk_matches | 注入给模型的话 |
|---|---|---|
| 是 | 是 | 文件的当前状态与本摘要描述一致 |
| 是 | 否 | 摘要所描述的文件状态已被后续修改覆盖，当前磁盘为更新状态 |
| 否 | 是 | 该摘要对应的快照已不在保留窗口内，无法核对；当前磁盘内容与本摘要不矛盾 |
| 否 | 否 | 该摘要对应的快照已不在保留窗口内，且磁盘内容已变化，无法判断方向 |

第四种只报"无法核对"，**不报方向**——因为确实不知道方向。把"不可达"和"更旧/更新"压进
一个枚举会让这一格没有名字，实现者只能自己发明。

### 三、压缩后的上下文形状

语义摘要就是新帧的内容，**只出现一次**。压缩后的解析结果仍然是四段结构（固定层、帧、
最近三轮、当前待办），不是"帧 + 三轮 + 末尾再来一段摘要"。固定层在压缩时点按当时状态
重建（当前的工具目录与当前的 AGENTS.md），因为压缩本身已经作废了前缀缓存。

摘要覆盖范围是"旧头部到最后三轮之前"，不含保留的三轮。

“压缩提交是原子的”：先完成模型调用，再用一次只覆盖"写帧 + 比较并交换 head"的短事务提交。
不复用 0002 里"事务"一词的数据库含义，避免与"事务绝不跨 IO"的纪律混淆。

### 四、读集表按（路径, 会话）一行

陈旧写校验（0009）需要每个调用者各自的"最后读到的哈希"，通知（0003）需要知道谁读过。
一张表两列键同时满足两者：

```
read_set(workspace_id, path, session_id, last_hash, last_read_seq)
```

按会话回收。它不是权威数据：丢了只少一条通知，不导致校验错误（校验时若无记录，按"未知"
处理，允许写入并在事件里标注）。

### 五、实际写入的观测来源

**实际写入集合 = 本次调用前后快照清单的差集，含墓碑条目。** 这个来源比工具自报可信，
因为快照由执行器在回收进程组之后生成，工具无权伪造。

工具自报的写入路径只作为补充（用于给出更精确的差异说明），不作为判定依据。差异（声明外
写入）记事件并告警，默认不阻塞（0016 与 0009 的分层）。

### 六、完整报文以引用形式落库

“完整请求与响应进事件表”的含义是：**以内容寻址引用加预览的形式进事件表，引用必须能还原
完整报文**。事件行本身不内联大段正文，与"大对象外置"一致。

### 七、外部改动的判据不用 git

回滚前判断"是否存在用户改动"时，不引入 git 概念。判据是：

> 当前磁盘内容与目标快照条目记录的哈希不一致，**且**这些差异不由任何已记录的、落在该
> 范围内的工具调用产生 → 视为外部改动，默认拒绝执行回滚。

这个判据只用快照已有的哈希与工具日志已有的记录，在非 git 工作区同样成立。

### 八、heredoc 正文的交付与换行

执行器把正文完整收进临时文件（或内存），以**只读文件描述符**交给工具。目标文件的原子
写入是写入类工具的义务（0012），不是执行器的职责——否则"实际写入路径"与工具自报都失去意义。

正文按字节原样交付，**不转换换行**。含 CRLF 的正文与真实 bash 行为一致（bash 也不转换）。
因此"我们比 bash 更宽松"这个说法作废：宽松会带来与 herestring 同类的静默差异——同一条命令
在 ita 里与在真实 shell 里写出的字节不同。

正文上限默认 1 MiB（见参数表）。

### 九、可调参数

以下是默认值。**它们不是不变量**：调整不需要新 ADR，但必须记录调整理由与生效日期。

| 参数 | 默认值 | 依据 |
|---|---|---|
| 快照保留 | 基线 + 64 个增量 | 到顶时最老两个合并进基线，不丢弃；覆盖一次长任务的回退深度 |
| 租约 TTL / 心跳 / 上限 | 120 秒 / 30 秒 / 2 小时 | TTL 短于人对崩溃恢复的容忍时间；心跳让长构建不被踢；上限防死循环任务永久占锁 |
| 批量提交窗口 | 5 毫秒或 256 条事件 | 5 毫秒对交互不可感知，同时能把并发工作区的事件合成一次落盘 |
| GC 宽限期 | 不短于租约 TTL，且活跃租约表是附加标记根；兜底 24 小时 | 把宽限期绑在在途工具生命周期上，比拍一个时长可靠 |
| 子 agent 深度 | 3 层 | 足够"主 → 探索 → 细分"，再深收益递减 |
| 子 agent 预算 | 单节点 ≤ 父剩余 25%，同层合计 ≤ 50% | 防指数放大 |
| 压缩触发阈值 | **85%** | 由项目负责人指定。代价是压缩调用自身所需余量更紧，实现时必须把压缩预留计入预算，否则压缩请求可能自己发不出去 |
| heredoc 正文上限 | 1 MiB | 代码文件远低于此；超过应走分段打补丁 |
| 事件正文预览 | 头 4 KiB + 尾 1 KiB | 报错通常在尾部，上下文通常在头部 |
| 超阈值文件 | 1 MiB | 见 0017 |
| `resolve` 耗时审视阈值 | 20 毫秒 | 超过说明在读路径做了本该在写路径做的事 |
| 事件表审视阈值 | 每工作区 200 MB | 触发归档的判据 |

**全部参数都要有配置入口。** 默认值写死在内核常量里，但读取路径统一走一个配置结构，
允许按项目、按工作区覆盖。参数表里每一项在实现时都必须出现在配置结构中，不允许以常量
形式散落在调用点——否则"可调"只是文档上的说法。

## 理由

这些定义缺一条，实现者就必须自己发明一条，而发明出来的东西彼此不兼容。评审列出的十条
里，有六条属于"两处各写一半，谁也没说全"，四条属于"给了形容词没给数"。前者的修法是
把定义集中到一处，后者的修法是给数并说明依据。

压缩阈值定在 85% 是负责人的明确要求。它的直接后果是压缩预留更紧：压缩调用本身要输入整个
上下文，如果预算里没有单独为它留位置，到 85% 时压缩请求会因超窗而失败。因此"压缩预留"
不是可选优化，而是这个阈值的必要配套。

参数可配置这条单独写出来，是因为它决定了实现的形状：配置结构必须在第一天就有，后面补等于
改所有调用点。

## 后果

好的方面：内核接口收敛；漂移消息四种组合各有名字；压缩结果形状唯一；写入观测有可信来源；
参数有出处。

代价：

- **`ResolveInput` 是较大的结构**，每次解析都要装好它，server 侧有组装成本。
- **85% 的阈值让压缩更晚发生**，单次压缩的输入更大、更慢，且失败时的重试窗口更窄。
- **参数可配置意味着行为依赖配置**，因此"同样的输入同样的输出"这条承诺要加上"同一配置下"。
- **CRLF 原样交付会让 Windows 上编辑过的文件在 heredoc 写入时保留回车**，某些工具可能不接受。
  这与 bash 一致，但用户可能感到意外。

需要重新审视的信号：如果压缩在 85% 频繁因超窗而失败，说明预留量算错了，应先修预留算法，
而不是降低阈值。

## 被否决的替代方案

**漂移状态保持三态枚举。** 少一列，实现更简单。不选的理由是"不可达且已变化"这一格没有
名字，实现者只能自己发明一种表述，而它恰好是最危险的一格（模型会误以为知道方向）。

**压缩后把摘要同时放进帧段与末尾。** 强调作用。不选的理由是同一件事以两种版本出现在上下文
里，模型遇到矛盾时行为不可预测，也破坏了可复现性。

**读集表按路径一行（只记最后读者）。** 表更小。不选的理由是陈旧写校验需要每个会话各自的
哈希，单行会把校验变成"与最后一次任意读取比较"，判断错误。

**实际写入由工具自报。** 实现简单。不选的理由是越界写入恰好不会被上报，而"声明可审"正是
要发现这种情况。

**参数写死为常量。** 简单且行为确定。不选的理由是不同的工作区（小脚本仓库与大单体）对
快照保留数、租约 TTL 的合理值差一个量级。
