# ITAgent 注释规范

> 本项目所有代码注释遵循本规范。规范变更先改本文件，再改代码。
> 开发文档写作规范见 `.w1mer/DOC_GUIDELINES.md`。

## 一、总则

| 原则 | 说明 |
|---|---|
| 写语义，不写历史 | 注释解释"代码做什么、为什么这么做"，不记录"哪个任务或讨论修的" |
| 禁止内部编号 | 注释里不出现 ROADMAP 编号（`05.1`）、ADR 编号（`ADR-0003`）、提交哈希。根因归档在 `.w1mer/`，代码里用语言描述问题本身 |
| 语言统一中文 | 术语保留英文（lease、landlock、CAS、heredoc 等），句子用中文 |
| 宁缺毋滥 | 只写代码无法自明处。不写 `// i += 1` 这类废话 |

## 二、函数与接口注释（`///`）

按四段结构书写，无内容的小节省略：

```rust
/// <一句话：做什么>。
///
/// <算法思路 / 为何这样设计，1-3 句>。
///
/// # 步骤
/// 1. <第 1 步做什么>
/// 2. <第 2 步做什么>
///
/// # 边界与前提
/// - <参数约束 / 前置条件 / 特殊值处理>
///
/// # 副作用
/// - <修改了哪些状态 / 可观察影响>
///
/// # 注意事项
/// - <调用时机 / 性能代价 / 与其它模块的隐含契约>
```

规则：

- `# 步骤` 只给多步骤的复杂函数；单步函数一句话描述即可，不堆小节。
- `# 边界与前提` 必须覆盖空输入、边界值、非法参数的处理方式。
- `# 副作用` 必须标注对外部状态的修改：写盘、发事件、获取或释放租约、修改 head。
- `# 注意事项` 写调用时机、性能代价、并发约束。跨进程的契约尤其要写明。

## 三、实现内部注释（`//`）

分步骤书写，步骤之间空一行，不写序号（改动步骤时无需重排）：

```rust
fn acquire(scope: &Scope, paths: &[PathId]) -> Result<Lease> {
    // 排序去重：固定顺序是原子获取多路径的前提，避免两个请求以相反顺序互等。
    let ordered = sort_and_dedup(paths);

    // 一次性尝试全部路径，任何一个被占立即整体失败并释放已拿到的部分。
    let lease = scope.try_acquire_all(&ordered)?;

    // 记录归属，供后续"文件已更新"通知反查读集。
    scope.record_holder(&lease)?;
    Ok(lease)
}
```

规则：

- 每个独立逻辑步骤前放一行，写这一段的意图，不写代码字面意思。
- 循环与分支内部只在关键判断处加注释；显然的代码不加。
- 长函数允许 `// ── 大段标题 ──` 做二级分区。

## 四、模块头注释（`//!`）

```rust
//! <模块职责一句话>。
//!
//! <关键不变量 / 与其他模块的契约，要点式列出>。
```

模块级不变量放这里，不散落在函数里。例如"本模块不做权限判定，只做文法解析"。

## 五、`unsafe` 与安全相关

每个 `unsafe` 块前必须有 `# Safety` 注释，写明调用者必须保证的前提，而不是复述代码。

```rust
// SAFETY: fd 由本函数刚创建且未移交他人，进程内无并发关闭路径。
unsafe { libc::dup2(fd, 1) };
```

沙箱、权限检查、文件路径规范化三处的注释必须写明"这是快速失败还是安全边界"——
混淆两者是本项目最容易埋下的漏洞。

## 六、禁止项

| 禁止 | 替代 |
|---|---|
| `// B003：...`、`// 05.1 ...`、`// ADR-0002 ...` | 语义描述 |
| `// hack / workaround / temp / 临时补丁` | 语义描述；确有简化时用 `// ponytail:` 标注已知上限 |
| `// TODO` 无主 | `// 未实现：<缺什么能力>，见 ROADMAP <编号>`（ROADMAP 编号允许出现在这一种情况：指向未完成工作） |
| 中英混杂、无标点的流水注释 | 完整中文句 |
| 与代码重复的注释 | 删除 |
