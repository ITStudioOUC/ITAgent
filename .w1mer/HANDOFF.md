## 每个批次的标准动作（顺序不能错）

上一轮出过三次「批次先关、reviewer 后到」的失误，白套了三层子批次。正确顺序是：

1. `w1mer batch-start <子任务>`。子批次加 `--type sub`，**默认是 `main`**，建错了要手改
   `.w1mer/STATE.json` 里的 `type` 与 `roles`。
2. 派 implementer（`ensure` + `role-join ... implementer`）与 explorer（只读，可同时开）；
   复审上一批要派 reviewer。三者并行是常态，不是可选项。
3. 实现 + 验证：`bash .w1mer/scripts/verify.sh all`，它依次跑 fmt、lint（分层门、
   门自测、纯净门、shellcheck、clippy、rustdoc）与 test（构建、nextest、doctest）。
   再跑一次 `bash .w1mer/scripts/verify.sh msrv`（需要 1.85.0 工具链）。每条看
   **退出码**，不要用管道过滤输出。
4. **先派 reviewer 并让它的 `role-join` 成功**，复审结论落盘并提交，再到第 5 步。
5. `bash .w1mer/scripts/bump_version.sh batch`（一个批次一次，脚本同步 Cargo.lock），
   放在**最后一次提交**里。
6. `w1mer batch-end <子任务>`，然后 `w1mer set task <子任务> --state done --effect "..."`。
7. 确认 `w1mer status` 显示 `COMPLETE` 且没有 `MISSING`。有缺失就只能开子批次补救。

## 跨批次必须记住的判断

- **内核纯净**：`ita-kernel` 零依赖（含 dev），禁止 IO/时钟/环境变量/线程。要读什么就
  作为参数传进来。脚本与 clippy 双门强制，破门直接失败。
- **分层与能力归属**：允许表与能力归属只写在 `.w1mer/scripts/check_layers.sh`，
  `STACK.md` 与 `STRUCTURE.md` 是镜像。新增成员、依赖或二进制先改脚本的表，再同步文档；
  门只看直接依赖，不是安全边界。
- **SQLite 的一次性窗口**：`ALTER TABLE` 只有 `ADD COLUMN`，没有 `ADD CONSTRAINT`；既有
  列上的 CHECK、既有列的 DEFAULT、既有外键的删除动作**全都改不了**，而迁移扫描器禁
  `DROP TABLE`，重建表这条退路也堵死。任何「某种取值下才成立」的规则，必须在建表那一版
  写死。这一条已经咬过三次（`size`/`mtime` 漏进 CHECK、`content_stored` 的默认值、
  `rebase_confirmed_by` 的空串）。
- **CHECK 求值为 NULL 时 SQLite 判通过**：写约束时每个分支都要显式 `IS NULL` /
  `IS NOT NULL`，只写 `IN (0, 1)` 会放过漏写的列。这条由用例反证过，不要凭直觉写。
- **表结构兜不住的三件事，靠写入路径承接**：`content_stored = 1` 的条目其 hash 必在
  `blobs` 里（06.6 写入时断言、06.8 回滚前核对）；目录行的 `mode` 与 `mtime` 允许为空
  （06.6 写入时填）；事件引用的会话属于同一工作区（只能写入时校验）。这三条目前只写在
  `CHANGES.md` 与计划文档里，`05_plan-06.md` 的验收列**还没有**，06.6 派发时要补进去。
- **审查是有效的**：`06.2` 这一支四轮复审抓出三个会导致永久数据缺陷的真 bug。不要跳过。
- **测试命名**：英文 snake_case + 上方一行 `///` 中文行为说明，规范在
  `.w1mer/COMMENT_GUIDELINES.md` 第六节。改英文不能丢中文名里的区分细节（「不报方向」
  要落成 `reports_unknown_direction`），这是最容易做砸的地方。
- **文档与代码同批提交**：ADR 的编辑性更正可以直接改；决策变化必须新写一份并在状态段
  互相指明。已被推翻的结论不要删，标成历史并写「压缩时以本段为准」。

## 已知的、有意为之的取舍

- 命令文法版本一不支持管道、通配符、变量展开；heredoc 只允许一个且不与 `<` 同现。
- 未加引号的分隔符只在正文不含 `$`、反引号、反斜杠时接受（真实 shell 会展开）。
- 快照超过 1 MiB 的文件只记录元数据（哈希、尺寸、修改时间），回滚时只报告、不删除不覆盖。
- 压缩阈值 85%，预留必须显式配置，否则构造预算时直接失败。
- `snapshot_entries.hash` **没有**指向 `blobs(hash)` 的外键，这是裁决结果不是遗漏：超阈值
  条目按内容算出哈希但正文不进内容存储，加外键会把 ADR 0017 规定的正常条目判成悬空。
- 迁移脚本在 `06.2` 期间改过多次，按旧版建过的库启动会报 `ScriptChanged`，删库重建即可。
  仓库未发布，这个代价是有意接受的。
- **CI 扩展有触发线，不要凭感觉提前上**：单个 job 构建 p50 超过 4–5 分钟再上 sccache；
  链接单步超过 10 秒或总构建超过 2 分钟再上 mold/lld；nextest 墙钟超过 2–3 分钟再拆
  测试分片矩阵；09/10 引入 `unsafe`/FFI 后加 ASan 常设门；首次发布前或传递依赖超过
  约 50 个时加 `cargo deny` 与供应链审计。当前 261 项测试约半秒、构建数秒，这些都不值得。
