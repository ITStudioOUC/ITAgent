## 说明

本史诗的子任务为初步拆分，进入前由 Explorer 结合当时的代码重新核对；被证伪的子任务应删除或改写，不硬做。

事件表的不可变性在表结构层没有约束（没有 UPDATE/DELETE 触发器），这是已裁决的已知缺口，由存储层只提供追加接口来守；后续批次不要把它当成新缺陷重开。`snapshot_entries.hash` 不指向 `blobs(hash)` 也是裁决结果：超阈值条目按内容算出哈希但正文不进内容存储，加外键会把正常条目判成悬空；这条由写入路径断言与回滚前核对承接。

## 追加子任务 06.1.1：迁移脚本指纹改用稳定哈希

06.1 的迁移运行器用 `DefaultHasher` 计算脚本指纹。标准库明确不保证该哈希跨版本稳定，而指纹不一致会以 `ScriptChanged` 硬失败：换一次 Rust 工具链后，所有既有数据库都会拒绝启动。仓库未发布时删库即可，但这个实现一旦进入用户手里就是数据可用性事故。

| 项 | 内容 |
|---|---|
| 验收行为 | `script_hash("")` 等于 `fnv1a64:cbf29ce484222325`，`script_hash("a")` 等于 `fnv1a64:af63dc4c8601ec8c`；同一内容多次计算结果相同，内容变化结果不同；`cargo nextest run -p ita-store --locked` 与 `verify.sh all` 全绿 |
| 主要文件 | `crates/ita-store/src/migrate.rs`、本计划文档 |
| 边界 | 只改指纹算法与对应的稳定性用例，不动迁移 SQL、表结构、事务边界与错误类型；不新增依赖 |
| 依赖 | 06.1 |

### 算法裁决

用 FNV-1a 64 并在结果前加 `fnv1a64:` 前缀。指纹的用途是发现“已发布的迁移被改过”，不是防篡改，因此不需要密码学强度；FNV-1a 的实现只有十几行、可写死已知向量、跨 Rust 版本稳定，也不需要新增依赖。前缀让未来换算法时能被识别，而不是把两种算法的十六进制混在一起。

被否决的方案：`sha2` 或 `blake3` 会为一个非安全用途引入依赖，而且 `blake3` 在存储层还要处理构建依赖；继续用 `DefaultHasher` 无法保证跨版本稳定，正是本条要修的问题；干脆不校验指纹会丢掉“迁移脚本被静默改动”的唯一检测。

### 兼容代价

指纹格式从裸十六进制变成带前缀的字符串，已按旧指纹建过的开发库启动时会报 `ScriptChanged`，删库重建即可。仓库未发布，这与 06.2 期间迁移脚本多次变化时的处理一致；发布后不得再用这种破坏性切换，只能新增迁移或引入指纹版本列。
