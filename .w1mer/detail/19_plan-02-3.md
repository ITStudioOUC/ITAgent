# EPIC 02.3 CI 方案核对

本文件记录 CI 的门怎么切、参数怎么选、以及本地绿而 CI 红的真实入口。工作流本身在
`.github/workflows/ci.yml`，这里只留判断依据。

## 结论

1. **切三个 job，不设 needs。** 编译型工作按"谁调用编译器"聚合：`lint` 同时承担 clippy 与内核
   纯净门，`test` 承担构建与测试，两者各有一套 target 与缓存；`fmt` 不编译，单独一个秒级 job。
   拆得更细会让 rust-cache 的缓存键（默认拼进 job 名）分裂，总分钟数反而上升；job 之间不共享
   文件系统，用 artifact 传编译产物是负收益。
2. **nextest 在零测试集上默认失败**（实测退出码 4）。曾用 `--no-tests=pass` 允许通过空集，该参数
   已在首批真实测试合入时删除，现在恢复默认语义。不要写进 nextest 配置文件：实测 `no-tests` 不是受支持的配置项，
   只会打印一条"忽略未知键"的警告后仍然失败。现在也不需要 `.config/nextest.toml`。
3. **纯净门与 workspace clippy 放同一个 job，并排在 clippy 之前。** 它的依赖与构建脚本两项检查
   不编译，先失败更省时间，且共用 target 与缓存。它只需要 bash、git、cargo 与 clippy 组件。
4. **clippy 与 build 两步带 `--locked`**；锁文件漂移由 `test` job 的独立检出兜底（它与 `lint` job 不共享工作目录）。纯净门脚本内部的 cargo 调用目前不带锁，已在后续子任务里补。

## 已知风险

| 风险 | 说明 | 处置 |
|---|---|---|
| stable 浮动 | 本地 1.97.0，CI 取当日最新 stable；新 lint 或 rustfmt 变更会让未改动的代码变红 | 红灯先查 stable 发版；要钉死需同时改 `rust-toolchain.toml` 与 action 版本 |
| 本地比 CI 松 | 本地 clippy 不带 `-D warnings`，且不跑纯净门 | 提交前跑 `.w1mer/scripts/check_kernel_purity.sh` |
| 空测试集被误判为通过 | 曾用 `--no-tests=pass` 掩盖 | 首批测试落地即删除，现已无该参数 |
| MSRV 声明无人验证 | `rust-version = "1.85"` 没有任何门检查，CI 全用 stable | 属已知空洞，需要时再加 MSRV job |
