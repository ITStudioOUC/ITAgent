## 追加子任务 02.8：分层与能力归属门

02.7 收口后，依赖方向与能力归属仍只写在文档里，没有任何可执行检查。本子任务把依赖方向、能力归属与二进制形态变成 CI 门，避免后续批次在无人察觉时引入跨层依赖或越权能力。

| 项 | 内容 |
|---|---|
| 验收行为 | 正常仓库运行 `bash .w1mer/scripts/check_layers.sh` 退出 0；注入 `ita-worker → ita-store` 时退出非零并指出被禁止的边与该 crate 的允许集合；注入 `ita-server` 普通依赖 `rusqlite` 时退出非零并指出能力归属；新建 workspace 成员但未登记允许表时退出非零；给任意非 `ita-cli` 成员加第二个 `[[bin]]` 时退出非零 |
| 主要文件 | `.w1mer/scripts/check_layers.sh`、`.github/workflows/ci.yml`、`.w1mer/codebase/STACK.md`、`.w1mer/codebase/STRUCTURE.md`、本计划文档 |
| 边界 | 只检查清单里声明的直接依赖，不看传递依赖；dev 与 build 依赖只参与 ita-* 归属检查，不参与能力归属检查；不引入新 crate、不改任何 Rust 源码 |
| 依赖 | 02.7 |

### 允许表的两处裁决

`ita-tools` 允许依赖 `ita-sandbox`：11.9 的构建沙箱与 11.14 的可用性门要直接使用 `Sandbox` trait 与平台探针；`Policy` 与 `Fidelity` 类型在 kernel，禁止这条边只会逼出第二份策略定义。

`ita-proto` 允许依赖 `ita-model`：12.7 的模型代理帧与 12.8 的流式转发要复用归一化消息类型。反向边 `ita-model → ita-proto` 仍然禁止，编码解码只能由 proto 消费 model 类型，不能反过来。

### 门的边界声明

这道门是分层守卫，不是安全边界。它看不见 `std::net`、`tokio::net`、构建脚本内的网络访问、传递依赖与 `pub use` 转出口；被允许使用 `libc` 的 crate 仍可直接发系统调用。无出网的真正边界仍是 ADR 0010 的沙箱策略。门通过只说明声明的直接依赖没有越层，不说明运行时没有旁路。

### 注入测试不需要刷新锁文件

`cargo metadata --no-deps` 只读清单，不解析依赖图，因此清单改动不会让 `--locked` 失败；实测在 `ita-worker` 注入路径依赖后，该命令仍退出 0。注入测试直接改清单、跑门、还原清单即可，不产生 `Cargo.lock` 改动。保留 `--locked` 只是为了与仓库其余 cargo 步骤一致。

### 文档同步规则

脚本内的常量是允许表与能力归属表的唯一权威来源。`STACK.md` 只做摘要并指向脚本；`STRUCTURE.md` 保留完整允许表作为人读镜像，并在小节开头写明脚本是权威。允许表的键必须与 workspace 成员双向一致，成员新增或改名时三处同一批次更新。
