## 说明

后续史诗的子任务为初步拆分，进入该史诗前由 Explorer 结合当时的代码重新核对；被证伪的子任务应删除或改写，不硬做。

## 追加子任务 02.8：分层与能力归属门

02.7 收口后，依赖方向与能力归属仍只写在文档里，没有任何可执行检查。本子任务把依赖方向、能力归属与二进制形态变成 CI 门，避免后续批次在无人察觉时引入跨层依赖或越权能力。

| 项 | 内容 |
|---|---|
| 验收行为 | 正常仓库运行 `bash .w1mer/scripts/check_layers.sh` 退出 0；注入 `ita-worker → ita-store` 时退出非零并指出被禁止的边与该 crate 的允许集合；注入 `ita-server` 普通依赖 `rusqlite` 时退出非零并指出能力归属；新建 workspace 成员但未登记允许表时退出非零；给任意非 `ita-cli` 成员加第二个 `[[bin]]` 时退出非零 |
| 主要文件 | `.w1mer/scripts/check_layers.sh`、`.github/workflows/ci.yml`、`.w1mer/codebase/STACK.md`、`.w1mer/codebase/STRUCTURE.md`、本计划文档 |
| 边界 | 只检查清单里声明的直接依赖，不看传递依赖；dev 与 build 依赖只参与 ita-* 归属检查，不参与能力归属检查；不引入新 crate、不改任何 Rust 源码 |
| 依赖 | 02.7 |

### 允许表的两处裁决

`ita-tools` 允许依赖 `ita-sandbox`：11.9 的构建沙箱与 11.14 的可用性门要直接使用 `Sandbox` trait 与平台探针；`Policy` 与 `Fidelity` 类型在 kernel，禁止这条边只会逼出第二份策略定义。

`ita-proto` 允许依赖 `ita-model`：12.7 的模型代理帧与 12.8 的流式转发要复用归一化消息类型。反向边 `ita-model → ita-proto` 仍然禁止，编码解码只能由 proto 消费 model 类型，不能反过来。

### 门的边界声明

这道门是分层守卫，不是安全边界。它看不见 `std::net`、`tokio::net`、构建脚本内的网络访问、传递依赖与 `pub use` 转出口；被允许使用 `libc` 的 crate 仍可直接发系统调用。无出网的真正边界仍是 ADR 0010 的沙箱策略。门通过只说明声明的直接依赖没有越层，不说明运行时没有旁路。

### 注入测试不需要刷新锁文件

`cargo metadata --no-deps` 只读清单，不解析依赖图，因此清单改动不会让 `--locked` 失败；实测在 `ita-worker` 注入路径依赖后，该命令仍退出 0。注入测试直接改清单、跑门、还原清单即可，不产生 `Cargo.lock` 改动。保留 `--locked` 只是为了与仓库其余 cargo 步骤一致。

### 文档同步规则

脚本内的常量是允许表与能力归属表的唯一权威来源。`STACK.md` 只做摘要并指向脚本；`STRUCTURE.md` 保留完整允许表作为人读镜像，并在小节开头写明脚本是权威。允许表的键必须与 workspace 成员双向一致，成员新增或改名时三处同一批次更新。

## 追加子任务 02.9：CI 验证体系补强

02.8 把分层门接进 CI 后，验证入口仍分散在 AGENTS、STACK、HANDOFF 与 `ci.yml` 四处；MSRV 声明 `1.85` 与实际使用的 let-chains（1.88 才稳定）不符，而 CI 只跑 stable，永远发现不了；分层门自身没有回归测试，文档也从未被 rustdoc 编译。本子任务把验证入口收成一处，并补上这三类缺口。

| 项 | 内容 |
|---|---|
| 验收行为 | `cargo +1.85.0 check --workspace --all-targets --locked` 退出 0（改写两处 let-chains，保持 MSRV 1.85）；`bash .w1mer/scripts/verify.sh all` 依次通过 fmt、lint、test 三阶段，`verify.sh msrv` 单独通过；`check_layers_test.sh` 用合成 metadata 覆盖十条失败路径、三条对照、一条错误路径与一次规则删除反证，且不改任何真实清单；`RUSTDOCFLAGS="-D warnings" cargo doc` 退出 0；`cargo test --doc` 被纳入 test 阶段；shellcheck 对 `.w1mer/scripts/*.sh` 无告警；CI 新增 MSRV job 并让 fmt/lint/test 三个 job 调用同一脚本 |
| 主要文件 | `.w1mer/scripts/verify.sh`、`.w1mer/scripts/check_layers_test.sh`、`.w1mer/scripts/check_layers.sh`、`.github/workflows/ci.yml`、`crates/ita-kernel/src/context/input.rs`、`crates/ita-store/src/migrate.rs`、`crates/ita-store/src/db.rs`、`Cargo.toml`、`AGENTS.md`、`.w1mer/codebase/STACK.md`、`.w1mer/HANDOFF.md`、`README.md` |
| 边界 | 不引入 sccache、mold、测试分片矩阵或 ASan：当前 261 项测试约半秒、冷构建数秒，这些手段的收益要等测试与构建进入分钟级才成立；`cargo deny` 与供应链审计留到单独批次；不改变任何业务行为，两处 let-chains 改写保持语义等价 |
| 依赖 | 02.8 |

### 参考 OxideJs 的取舍

同组织的 OxideJs 仓库 CI 采用 `fmt`、`clippy`、`build` 三个独立 job，`test` 经 `needs: [build]` 复用 sccache 产物，测试按包与用例分成矩阵并行，另有 ASan 常设门与依赖 `deny.toml`。可借鉴且与本仓规模匹配的三点是：并发组只在 PR 上取消旧 run（main 保留每个提交的完整记录）；`test` 与构建共享编译产物（本仓 test job 内部先 build 再 nextest，已经满足）；用独立 job 固定 MSRV 或工具链。暂不借鉴的是 sccache、mold、测试分片与 ASan：前两者服务于分钟级构建，分片服务于分钟级测试，ASan 要等 09 与 10 引入 `unsafe` 后才有意义。`deny.toml` 属于供应链审计，单独批次处理，避免本批把网络数据库拉进每次推送。

### MSRV 的裁决

保留 `rust-version = "1.85"`，不升到 1.88。1.85 是 edition 2024 的起始版本，仓库一开始就锚在这里；实际只有两处 let-chains 越界，改写成嵌套 `if let` 是等价且更小的改动。升 MSRV 会让门槛无理由抬高四个月，而 CI 加一个 1.85 job 就能把声明变成事实。相应地在 `Cargo.toml` 注明 1.85 下不得使用 let-chains。

### 门自测的做法

`check_layers.sh` 增加 `--metadata <文件>` 入口，只供自测与离线诊断使用；正常路径仍自己跑 `cargo metadata`。入口要校验 `packages` 的 id 集合等于 `workspace_members`，否则传全量 metadata 时会把第三方包当成未登记成员，报错原因会失真。参数解析放在 `cd` 与 `cargo metadata` 之前，`--metadata` 模式不依赖当前目录。

`check_layers_test.sh` 先取一份真实 `--no-deps` 元数据作为基线并断言它通过，再用 Python 在临时目录里生成变异样本，覆盖：普通依赖跨越禁止边、dev 与 build 的 ita 边被拒、dev 与 build 的能力依赖放行、`rename` 不能绕过包名识别、反向依赖 `ita-cli` 被拒、未登记二进制、未登记成员、陈旧成员条目、`packages` 与 `workspace_members` 不一致，以及 `--metadata` 指向不存在文件的错误路径。这样不需要改真实 `Cargo.toml`，也不会污染 `Cargo.lock`。门一旦被改坏，自测会先红，而不是静默放行；另做一次“删掉 rusqlite 能力规则后自测必须变红”的反证，确认自测真的在测门。

### 验证入口的分层

`verify.sh` 有五个阶段：`fmt`、`lint`、`test`、`msrv`、`all`。`lint` 包含分层门、门自测、内核纯净门、shellcheck、clippy（`--all-targets`）与 rustdoc（`-D warnings`）；`test` 包含构建、nextest 与 doctest；`msrv` 用 `cargo +1.85.0` 跑全目标检查，并先断言 rustc 版本确实是 1.85。CI 的四个 job 分别调用 `verify.sh fmt|lint|test|msrv`，不再各自抄命令。`all` 只含 fmt、lint、test，不含 msrv，因为本地不一定装了 1.85 工具链；这条要在脚本帮助与文档里写明，避免 `all` 的名字造成误解。

shellcheck 只有一条规则：缺失即失败，并打印安装命令；用 `SHELLCHECK` 环境变量可以指向自定义二进制。不引入“本地跳过、CI 失败”的双轨，否则又会回到本地比 CI 松的老问题。当前没有任何 feature，clippy 不加 `--all-features`，等第一个 feature 落地时同批加。

### README 的写法

不写版本号，也不写“下一步做什么”，只写“已经有什么、没做什么”，并明确“当前进度以 ROADMAP 为准”。版本号在 `Cargo.toml` 与 ROADMAP 的 effect 里已经有两处，README 再抄一份只会重复漂移。

### 四个模块头的边界

四个 crate 都位于内核之外，但“内核之外”不等于“可以出网”。`ita-model` 只做归一化与编解码，不持有 HTTP 客户端与凭据；`ita-proto` 只定义信封与帧，不建立连接；`ita-tools` 只做清单、ABI 与注册表，取源与构建在沙箱里执行；`ita-workflow` 只做 DSL、静态检查与状态推导，不执行节点、不碰存储。这套措辞与 STACK 的“模型流量只经 server 代理”“worker 与执行器默认无网”一致。

### 06 验收列的补齐

表结构只能保证列与列的形态，其余约定必须由写入路径承接：06.3 的 seq 取自 `workspace_seq` 计数器而不是表内最大值，事件引用的会话属于同一工作区；06.4 的冲突提交不消耗 seq，帧引用的会话属于同一工作区；06.5 先写内容到最终哈希路径再插入 `blobs` 行，中断只留下无引用文件；06.6 的 `content_stored = 1` 条目其哈希必在 `blobs` 里（写入路径断言，不加外键，否则超阈值条目会被判成悬空），目录行写 `mode` 与 `mtime`、文件行写 `mode`，超阈值条目带修改时间；06.7 重挂父边时父子快照属于同一工作区；06.8 范围外不碰并在残留清单写明路径与原因，写回前核对有内容条目的 `blobs`，缺失内容时整次拒绝并列出路径。事件表的不可变性与 `snapshot_entries.hash` 没有外键这两处已裁决的缺口写进计划说明，不在验收列重复。这些写进验收列后，06.3 至 06.8 派发时探索者能直接看到。
