# EPIC 02.2 探针结论

本文件回答一个问题：内核纯净门该怎么写才能真正拦住 IO 与时钟，并且不误伤后续要在内核之外做 IO 的 crate。全部结论都在仓库副本里实测过，命令与输出附在下面，实施者可以照着敲。

## 结论

1. **配置放 `crates/ita-kernel/clippy.toml`，不放仓库根。** 实测 clippy 按被检 crate 的清单目录查找配置文件：从仓库根执行 `cargo clippy -p ita-kernel` 时读到的是 crate 内那份；一个成员有配置、另一个成员没有时，只有前者报错。放根目录会让条目作用于全部成员，后续 store、sandbox、exec 这些必须做 IO 的 crate 会被误伤。
2. **只写 clippy.toml 不够，必须在 lib.rs 把 lint 提升为 deny。** 实测只配 clippy.toml 时，命中条目只是一条警告，`cargo clippy -p ita-kernel` 退出码为 0，不满足"clippy 失败"的验收。在 lib.rs 增加 `#![deny(clippy::disallowed_types)]` 与 `#![deny(clippy::disallowed_methods)]` 后，裸跑 clippy 以 101 退出，而 `cargo build` 正常通过，因为 clippy 的 lint 不参与 rustc 编译。
3. **类型条目和方法条目都要写。** 方法条目抓的是函数调用，类型条目抓的是源码里出现的类型路径。`std::fs::File::open` 这种写法在方法表里没有对应条目，靠 `std::fs::File` 类型条目拦住，实测有效。
4. **依赖断言用 `cargo tree -p ita-kernel --edges normal,build --prefix none`，判据是输出恰好一行且以 `ita-kernel v` 开头。** 不用 `cargo metadata`：它的输出是 JSON，判据要额外依赖 jq 或 python 解析；cargo tree 是 cargo 自带子命令，判据能写成一行 shell。`--edges normal,build` 排除 dev-dependencies，因此测试用具允许，随产物发布的依赖一个都不许有：实测只有 dev 依赖时脚本通过，普通依赖与构建依赖各让输出多出一行并失败。
5. **额外加一条 `build.rs` 存在性检查。** 构建脚本在编译期能做任意 IO，也能把依赖藏进构建图，依赖断言和 lint 都看不见它。
6. **无效条目不会让 `-D warnings` 失败，脚本要单独抓。** 实测 clippy.toml 里写错的条目只打印一条普通警告，加 `-D warnings` 后退出码仍是 0，因为该诊断不走 lint 通道。脚本用 `grep "does not refer to a reachable"` 兜住这一层。
7. **`#![deny(missing_docs)]` 保留，不降级为 warn。** 内核的公开面就是它对外交付的契约，缺一条文档说明意味着这个类型还没想清楚；代价是每个公开枚举变体与结构体字段都要写一行注释，成本可预期。保留 deny 的好处是本地 `cargo build` 就会失败，而不是等 CI 一次报出几十条警告。若探索期确实被卡住，再降到 warn 并把 `-D warnings` 放进 CI，但要接受本地构建放过缺失文档。
8. **通配符不支持。** 实测 `std::fs::*` 这类写法会被判为"不指向可达类型"，条目必须逐条列到具体类型或函数，因此配置有六十余条；每条都可单独审阅，这是可接受的代价。

## 实测环境与做法

环境是 Linux，cargo 1.97.0，rustc 1.97.0，clippy 0.1.97，edition 2024。实验都在 `/tmp` 下的仓库副本里进行，工作树没有被改动。仓库副本里额外建过一个两成员工作区，用来验证配置是否按 crate 隔离。

## 要写的三处内容

### 一、新增 `crates/ita-kernel/clippy.toml`

```toml
# ita-kernel 的纯净门配置。
#
# cargo clippy 按被检 crate 的清单目录查找 clippy.toml，所以本文件只约束本 crate，
# 工作区其他成员（存储、网络、执行器）不受影响。
#
# 目录段不支持通配符，条目必须写到具体类型或函数；写错的条目会被 clippy 报成
# "不指向可达类型"，配合 `-D warnings` 直接失败，因此拼写错误不会静默失效。

# 拿到就必然做 IO 的类型：文件句柄、套接字、子进程、线程句柄。
disallowed-types = [
  "std::fs::DirBuilder",
  "std::fs::File",
  "std::fs::Metadata",
  "std::fs::OpenOptions",
  "std::fs::ReadDir",
  "std::net::TcpListener",
  "std::net::TcpStream",
  "std::net::UdpSocket",
  "std::process::Child",
  "std::process::Command",
  "std::process::Stdio",
  "std::thread::Builder",
  "std::thread::JoinHandle",
  "std::thread::Thread",
]

disallowed-methods = [
  # 读时钟：内核里的时间只能由调用方作为参数传入。
  "std::time::Instant::elapsed",
  "std::time::Instant::now",
  "std::time::SystemTime::elapsed",
  "std::time::SystemTime::now",
  # 文件系统。
  "std::fs::canonicalize",
  "std::fs::copy",
  "std::fs::create_dir",
  "std::fs::create_dir_all",
  "std::fs::hard_link",
  "std::fs::metadata",
  "std::fs::read",
  "std::fs::read_dir",
  "std::fs::read_link",
  "std::fs::read_to_string",
  "std::fs::remove_dir",
  "std::fs::remove_dir_all",
  "std::fs::remove_file",
  "std::fs::rename",
  "std::fs::set_permissions",
  "std::fs::symlink_metadata",
  "std::fs::write",
  # 网络。
  "std::net::TcpListener::bind",
  "std::net::TcpStream::connect",
  "std::net::UdpSocket::bind",
  # 进程与线程：一旦能起子进程或后台线程，就不再是可重放的纯函数。
  "std::process::abort",
  "std::process::exit",
  "std::thread::Builder::new",
  "std::thread::park",
  "std::thread::park_timeout",
  "std::thread::scope",
  "std::thread::sleep",
  "std::thread::spawn",
  "std::thread::yield_now",
  # 环境变量：同一份输入在不同环境下会得到不同结果。
  "std::env::args",
  "std::env::args_os",
  "std::env::current_dir",
  "std::env::current_exe",
  "std::env::remove_var",
  "std::env::set_var",
  "std::env::temp_dir",
  "std::env::var",
  "std::env::var_os",
  "std::env::vars",
  "std::env::vars_os",
  # 写标准输出与标准错误也是 IO；print! 与 println! 展开成这两个内部函数。
  "std::io::_eprint",
  "std::io::_print",
  "std::io::stderr",
  "std::io::stdin",
  "std::io::stdout",
]
```

### 二、`crates/ita-kernel/src/lib.rs` 增加两行

放在现有 `#![forbid(unsafe_code)]` 与 `#![deny(missing_docs)]` 之后：

```rust
#![deny(clippy::disallowed_methods)]
#![deny(clippy::disallowed_types)]
```

这两行是 clippy.toml 生效的前提。若只保留配置而 lint 停在 warn 级，裸跑 clippy 会以 0 退出，验收无法通过。

### 三、新增 `.w1mer/scripts/check_kernel_purity.sh`，并 `chmod +x`

```bash
#!/usr/bin/env bash
# 内核纯净门：ita-kernel 不得依赖任何带 IO 的 crate，也不得读时钟、碰文件系统、
# 起子进程或线程、读环境变量。
#
# 依赖部分由 cargo tree 断言，只允许 dev-dependencies；行为部分由 clippy 的
# disallowed-types 与 disallowed-methods 断言，条目在 crates/ita-kernel/clippy.toml。
# 任一条件不满足即非零退出，可直接作为 CI 的一步。
set -euo pipefail

cd "$(git rev-parse --show-toplevel)"

die() { printf '内核纯净门失败：%s\n' "$*" >&2; exit 1; }

# 构建脚本在编译期能做任意 IO，也能把依赖藏进构建图，因此必须不存在。
if [ -e crates/ita-kernel/build.rs ]; then
  die "ita-kernel 不应有 build.rs"
fi

# cargo tree 默认会把 dev 依赖也画出来，这里只要 normal 与 build 两类：
# 测试用具允许，随产物发布的依赖一个都不许有。
deps=$(cargo tree -p ita-kernel --edges normal,build --prefix none)
if [ "$(printf '%s\n' "$deps" | wc -l)" -ne 1 ] || ! printf '%s\n' "$deps" | grep -qx 'ita-kernel v.*'; then
  printf '实际依赖树：\n%s\n' "$deps" >&2
  die "ita-kernel 出现普通或构建依赖，只允许 dev-dependencies"
fi

# clippy 按被检 crate 的清单目录查找 clippy.toml，条目因此只作用于内核。
# 写错的条目只打印普通警告、不受 -D warnings 约束，这里单独抓一次。
if ! lint_output=$(cargo clippy -p ita-kernel --all-targets -- -D warnings 2>&1); then
  printf '%s\n' "$lint_output" >&2
  die "内核出现被禁止的 IO 调用，见上面的 clippy 诊断"
fi
if printf '%s\n' "$lint_output" | grep -q 'does not refer to a reachable'; then
  printf '%s\n' "$lint_output" >&2
  die "clippy.toml 有条目不指向可达的类型或函数，需要修正拼写"
fi

printf '内核纯净门通过\n'
```

## 验证命令

通过态：

```
cargo clippy -p ita-kernel
bash .w1mer/scripts/check_kernel_purity.sh
cargo build --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

失败态（改完立刻还原）：

```
printf '\n/// 探针：读时钟。\npub fn probe_now() -> std::time::Instant {\n    std::time::Instant::now()\n}\n' >> crates/ita-kernel/src/lib.rs
cargo clippy -p ita-kernel
bash .w1mer/scripts/check_kernel_purity.sh
```

两条命令都应非零退出，第一条的报错是 `use of a disallowed method` 并指向 `#![deny(clippy::disallowed_methods)]`，第二条的报错来自 clippy 诊断的转述。随后删掉探针函数，两条命令恢复零退出。

## 实测结果

| 场景 | 期望 | 实测 |
|---|---|---|
| 配置在 crate 内，从仓库根执行 clippy | 命中条目 | 命中，报 `use of a disallowed method` |
| 配置在仓库根，从仓库根执行 clippy | 命中条目 | 命中，说明向上查找同样成立 |
| 两成员工作区，只给其中一个 crate 配 clippy.toml | 只有该成员报错 | 符合，另一成员零告警 |
| 只配 clippy.toml，不给 deny 属性 | 仅警告 | 警告一条，退出码 0 |
| 加两行 deny 后裸跑 clippy | 编译失败 | 退出码 101 |
| 加两行 deny 后 `cargo build` | 正常通过 | 退出码 0 |
| 条目写成通配符 `std::fs::*` | 应能覆盖目录 | 不支持，报"不指向可达类型"，必须逐条列 |
| 条目拼写错误加 `-D warnings` | 期望失败 | 退出码仍是 0，只打印普通警告 |
| 63 条配置逐条触发实测 | 全部触发 | 61 条触发；未触发的两条是 `std::env::set_var` 与 `std::env::remove_var`，edition 2024 里它们是 unsafe 函数，内核禁 unsafe 时不可达 |
| 依赖树：零依赖 | 一行 | 一行，`ita-kernel v0.1.0 (...)` |
| 依赖树：只有 dev-dependencies | 通过 | 通过；注意默认 `cargo tree` 会画出 dev 段，必须带 `--edges normal,build` |
| 依赖树：普通依赖或构建依赖 | 失败并回显 | 失败，回显两行依赖树 |
| 存在 build.rs | 失败 | 失败，提示内核不应有构建脚本 |
| 脚本从 crate 子目录执行 | 通过 | 通过，脚本自己切到仓库根 |

另外记一条与下一批有关的实测：`cargo nextest run -p ita-kernel` 在当前零测试状态下以 "no tests to run" 退出非零，02.3 的 CI 需要 `--no-tests=pass`，或者在内核里补一个最小的纯函数单测。

## 照做步骤

1. 写 `crates/ita-kernel/clippy.toml`。
2. 在 `crates/ita-kernel/src/lib.rs` 的 crate 属性区加两行 deny。
3. 写 `.w1mer/scripts/check_kernel_purity.sh` 并 `chmod +x`。
4. 跑通过态的四条命令。
5. 注入探针跑失败态，确认两条命令都以非零退出，然后删除探针。
6. 跑三件套。nextest 一步用 `cargo nextest run -p ita-kernel --no-tests=pass`，否则会因零测试失败。
7. 提交前用 `.w1mer/scripts/bump_version.sh batch` 把版本推进一位（具体值取决于 02.1 是否已完成批次收尾），再 `batch-end`。
8. 建议提交信息：`feat: 加内核纯净门，禁止时钟与 IO 并断言零依赖`。

## 风险与遗留

- **配置查找方式属于 clippy 的实现细节。** 目前按 crate 目录解析，未来版本若改成只读工作区根目录，条目会整体失效或整体生效。依赖断言不依赖 clippy，因此内核零依赖这条底线仍守得住，但 IO 调用会漏检。若要自动防回归，02.3 可以在临时副本里注入探针并断言失败，作为 CI 的一步。
- **条目覆盖的是 std 的具体路径。** 新 API 不在表内，例如 `std::fs::exists` 与 `std::io::copy`；每加一个内核模块时顺手复核一次，比一次列全更现实。
- **平台相关路径没有入表。** 例如 `std::os::unix::fs::symlink` 只在 Linux 可达，写进配置会在其他平台变成无效条目，从而让脚本失败。本项目按 Linux 交付，暂不处理。
- **Instant 与 SystemTime 类型本身没有禁。** 时间作为参数传入内核是允许的，禁掉类型会让时间只能换自定义类型传参。若评审认为内核对时间类型的任何引用都算越界，把这两条加进类型表即可，代价是接口要多一层转换。
- **dev-dependencies 允许，意味着 rand、proptest 可以进内核测试。** 它们不进产物，但会写进 Cargo.lock。若要求内核依赖表绝对为空，把 dev 也禁掉，代价是性质测试不能借用外部库。
- **脚本依赖 `git rev-parse` 定位仓库根。** 在导出的源码包或非 git 环境里会失败，CI 的 checkout 步骤满足前提。
- **拼写错误只能靠脚本兜。** 开发者若绕过脚本直接跑 clippy，错误条目只打印普通警告，看起来一切正常。提交前跑脚本这一段要在 02.3 的 CI 里固定下来，或者接进 pre-commit。
