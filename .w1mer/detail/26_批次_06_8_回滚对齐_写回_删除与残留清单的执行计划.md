# 批次 06.8 回滚对齐：写回、删除与残留清单的执行计划

拆分依据给 06.8 的验收是"范围内新建文件被删、超阈值只报告，范围外不碰并在残留清单写明路径、尺寸与原因；写回前核对有内容条目的 blobs，缺失内容的路径不写回并在残留清单标注'内容缺失'，存在其它外部改动时默认拒绝"。核对基线 80a67a2 的已提交代码与 ADR 0005、0017、0018 之后，结论是：**验收口径成立且不需要改，但它依赖的六件事必须写进计划，否则实现者会在细节上做对数值、做错语义。** 六件事分别是：回滚对齐是独立动词而不是折进 `create_snapshot`（ADR 0005 明确"对齐不是一次写回"）；回滚目标是链上某个快照的有效状态，需要先沿链折叠而不是只读目标快照自己的清单（06.7 的 squash 与 06.8 的对齐共用同一套折叠算法）；范围（工具清单声明的写集）是参数而不是存储层自己算的（存储层不解析工具清单）；超阈值条目只报告、从不删除、从不覆盖（ADR 0017）；写回前核对 blobs，缺失内容标注"内容缺失"（0006 的 blobs 断言的读路径延伸）；存在其它外部改动时默认拒绝，除非显式强制（ADR 0018 第七节）。文件规划 `align.rs`、`restore.rs`、`residual.rs` 与现状吻合，另需在 `db.rs` 加错误变体与公开动词、在 `lib.rs` 声明模块。

## 结论

1. 06.8 的原始拆分成立。表结构（`snapshots` 与 `snapshot_entries`）与 ADR 0005、0006、0017、0018 都没有把这项工作推到别的批次，也没有出现让验收口径失效的变更。需要改写的是"怎么做"，不是"做什么"。
2. **回滚对齐是独立动词，不是折进 `create_snapshot`。** ADR 0005 明确"文件回滚是一次对齐，不是一次写回"，四种情况（写回、覆盖、墓碑删除、范围内新建删除）都要处理。06.6 的 `create_snapshot` 只按链追加，06.7 的 squash 改写链，06.8 的对齐是第三种独立职责：读有效状态、对齐磁盘、输出残留清单。
3. **回滚目标是链上某个快照的有效状态，需要先沿链折叠。** 目标快照是链上的一个节点（基线加增量），它的有效状态是基线到目标（含目标）的折叠结果。06.7 的 squash 折叠 B、I1、I2 更新基线，06.8 的对齐折叠基线到目标。两者共用同一套折叠算法，必须参数化折叠范围，这是本批唯一的跨表设计决定。
4. **范围（工具清单声明的写集）是参数，不是存储层自己算的。** 存储层不解析工具清单，范围由调用方（server/执行器）从清单读出后传入。这决定了"范围内新建文件被删"（情况 4）与"范围外不碰"的区分：存储层只对范围内的路径做删除，范围外的路径不碰、只进残留清单。
5. **超阈值条目只报告、从不删除、从不覆盖。** ADR 0017 明确"超阈值文件只报告，从不删除、从不覆盖"。`content_stored = 0` 的条目带 `hash`、`size`、`mtime`，对齐时只进残留清单（带尺寸），不写回、不删除。
6. **写回前核对 blobs，缺失内容标注"内容缺失"。** 06.6 的写入路径断言 `content_stored = 1` 的条目其哈希必在 blobs 里。06.8 的读路径延伸这条：写回前查 blobs 行，缺失则不写回、在残留清单标注"内容缺失"。这是 06.6 写入断言的读路径对应物。
7. **存在其它外部改动时默认拒绝，除非显式强制。** ADR 0018 第七节判据是"磁盘内容与目标快照记录的哈希不一致，且差异不由已记录的工具调用产生 → 视为外部改动，默认拒绝执行回滚"。存储层能检查"磁盘与目标哈希不一致"（有目标哈希与磁盘），但不能检查"差异不由已记录工具调用产生"（那需要事件日志）。因此存储层的对齐动词把"磁盘与目标哈希不一致"的差异报告出来，默认拒绝，调用方用 `force` 覆盖。
8. 06.8 不追加事件、不写回收、不做 squash、不算事件 seq、不写 `events` 或 `nodes` 行、不新增迁移。

## 二、回滚对齐的实际形状

### 2.1 回滚对齐是独立动词，不是折进 `create_snapshot`

`Store::align(&mut self, scope, target: &CheckpointId, range: &[String], force: bool) -> Result<AlignResult, StoreError>` 是公开动词。它读目标快照的有效状态、对齐磁盘、输出残留清单。

`target` 是回滚目标（链上某个快照的 `CheckpointId`）。`range` 是工具清单声明的写集（范围内的路径）。`force` 是是否强制对齐（即使存在外部改动）。

对齐不折进 `create_snapshot` 的理由有三条。第一，ADR 0005 明确"文件回滚是一次对齐，不是一次写回"，四种情况（写回、覆盖、墓碑删除、范围内新建删除）都要处理，`create_snapshot` 只按链追加，不处理这四种情况。第二，对齐是读有效状态、对齐磁盘、输出残留清单的独立职责，与 06.6 的追加、06.7 的链改写是不同职责，混进 `create_snapshot` 会让"这一批只有一个目的"失效。第三，server 可能在创建快照与对齐之间做别的（比如打日志），对齐作为独立动词让 server 显式控制时机。

### 2.2 回滚目标是链上某个快照的有效状态，需要先沿链折叠

目标快照是链上的一个节点（基线加增量）。它的有效状态是基线到目标（含目标）的折叠结果。折叠算法是左结合的覆盖加墓碑删除：从一个空映射开始，按链序（基线到目标）遍历每个快照的清单，对每条条目：

- 墓碑：从映射删掉该路径。
- file 或 dir：把该路径设为该条目（覆盖既有）。

结果是有效状态。折叠满足结合律，与 06.7 的 squash 共用同一套算法。06.7 折叠 B、I1、I2 更新基线，06.8 折叠基线到目标。两者共用同一套折叠算法，必须参数化折叠范围。

折叠算法是 06.7 与 06.8 的公共依赖。06.7 的 squash 在 `squash.rs`，06.8 的对齐在 `align.rs`。两者共用折叠，因此折叠算法应提取为共享模块（如 `fold.rs` 或放进 `entries.rs`），由 squash 与 align 共同调用。06.7 在进行中，折叠可能在 `squash.rs`，06.8 应把它提取为共享模块。

### 2.3 范围（工具清单声明的写集）是参数，不是存储层自己算的

存储层不解析工具清单。范围由调用方（server/执行器）从清单读出后传入。这决定了"范围内新建文件被删"（情况 4）与"范围外不碰"的区分：存储层只对范围内的路径做删除，范围外的路径不碰、只进残留清单。

`range` 是声明写集的路径列表。对齐时：
- 范围内的路径：按有效状态对齐（写回、覆盖、墓碑删除、范围内新建删除）。
- 范围外的路径：不碰，只进残留清单（带路径、尺寸、原因）。

### 2.4 超阈值条目只报告、从不删除、从不覆盖

`content_stored = 0` 的条目是超阈值条目，带 `hash`、`size`、`mtime`。ADR 0017 明确"超阈值文件只报告，从不删除、从不覆盖"。对齐时：
- 超阈值条目不进写回（没有内容可写回）。
- 超阈值条目不进删除（不删除）。
- 超阈值条目进残留清单（带尺寸）。

### 2.5 写回前核对 blobs，缺失内容标注"内容缺失"

06.6 的写入路径断言 `content_stored = 1` 的条目其哈希必在 blobs 里。06.8 的读路径延伸这条：写回前查 blobs 行，缺失则不写回、在残留清单标注"内容缺失"。这是 06.6 写入断言的读路径对应物。

写回前的核对：
1. 读有效状态里的 `content_stored = 1` 条目。
2. 对每条，查 blobs 行是否存在。
3. 存在则从 CAS 读内容、写回磁盘。
4. 缺失则不写回、进残留清单标注"内容缺失"。

### 2.6 存在其它外部改动时默认拒绝，除非显式强制

ADR 0018 第七节判据是"磁盘内容与目标快照记录的哈希不一致，且差异不由已记录的工具调用产生 → 视为外部改动，默认拒绝执行回滚"。存储层能检查"磁盘与目标哈希不一致"（有目标哈希与磁盘），但不能检查"差异不由已记录工具调用产生"（那需要事件日志）。因此存储层的对齐动词把"磁盘与目标哈希不一致"的差异报告出来，默认拒绝，调用方用 `force` 覆盖。

外部改动的检测：
- 对有效状态里的每条 `content_stored = 1` 条目，读磁盘内容、算哈希。
- 若磁盘哈希与目标哈希不一致，且该路径不在有效状态里（或不是超阈值条目），则是外部改动。
- 若存在外部改动且 `!force`，返回 `AlignRefusedExternal` 错误，整笔回滚。
- 若 `force`，则覆盖。

## 三、ADR 对回滚对齐的硬要求

与 06.8 相关的决策分布在四份 ADR 里，逐条对照如下。

| 要求 | 出处 | 06.8 怎么落地 |
|---|---|---|
| 文件回滚是一次对齐，不是一次写回：四种情况（写回、覆盖、墓碑删除、范围内新建删除） | 0005 决策段 | `align` 是独立动词，处理四种情况 |
| 回滚保证边界：只保证工作区内、工具清单声明范围内、被工具修改过的文件；范围外不碰，输出残留清单 | 0005 决策段 | 范围是参数，范围外不碰、进残留清单 |
| 回滚时检测到范围内存在外部改动，默认拒绝执行，除非显式要求强制 | 0005 决策段与 0018 第七节 | 存储层报告差异、默认拒绝，`force` 覆盖 |
| 超过大小阈值的文件只报告、不删除也不覆盖 | 0006 与 0017 决策段 | 超阈值条目只进残留清单（带尺寸），不写回、不删除 |
| 残留清单是回滚结果的必要组成部分：至少包含路径、尺寸、原因（超阈值、范围外写入、后台进程遗留） | 0017 决策段 | 残留清单带路径、尺寸、原因 |
| 回滚即对齐：范围内、有内容记录的文件与删除墓碑，不含因超过阈值未记录内容的文件 | 0017 决策段 | 对齐的语义是"范围内、有内容记录的文件与墓碑"，超阈值只报告 |
| 外部改动的判据不用 git：磁盘内容与目标快照哈希不一致，且差异不由已记录工具调用产生 | 0018 第七节 | 存储层检查磁盘与目标哈希不一致，报告差异、默认拒绝 |
| 全部参数都要有配置入口，不允许以常量形式散落在调用点 | 0018 第九节 | 范围与 `force` 是参数，存储层不硬编码 |

三处需要特别说清的核实结果。

**第一，`snapshot_entries` 表不带工作区列，按快照 id join 回 `snapshots` 才能确定归属。** 06.6 的读路径跨工作区校验必须 join `snapshots` 表。06.8 的对齐读有效状态同样要 join，不能只看 `snapshot_entries`。

**第二，`content_stored = 0` 的条目必须带 `mtime`。** `0002_content.sql` 的形态 CHECK 已强制"未存内容必带修改时间"。06.8 的残留清单靠 `mtime` 判断文件在快照之后动过没有，缺 `mtime` 的超阈值条目在写入路径就被拒。

**第三，`workspaces.root_path` 是工作区磁盘根路径。** 06.8 的对齐要扫工作区磁盘，`root_path` 是扫描的根。存储层从 `workspaces` 表读出 `root_path`，对齐以它为根。

## 四、改写后的验收标准

每条都能写成一个测试，括号里写明它守的是什么。

1. **范围内新建文件被删。** 在有效状态里对某路径写墓碑，磁盘上该路径存在（快照之后新建），调用 `align`，断言该路径被删除、残留清单里没有它。守的是"情况 4：范围内新建删除"。
2. **超阈值条目只报告、不删除、不覆盖。** 在有效状态里对某路径写 `content_stored = 0` 的超阈值条目，磁盘上该路径存在，调用 `align`，断言该路径不被删除、不被覆盖、进残留清单（带尺寸）。守的是"超阈值只报告"。
3. **范围外不碰并在残留清单写明路径、尺寸与原因。** 在有效状态里对某路径写条目，但该路径不在 `range` 里，调用 `align`，断言该路径不被删除、不被覆盖、进残留清单（带路径、尺寸、原因）。守的是"范围外不碰"。
4. **写回前核对有内容条目的 blobs。** 在有效状态里对某路径写 `content_stored = 1` 的条目，但哈希不在 blobs 里，调用 `align`，断言该路径不被写回、进残留清单标注"内容缺失"。守的是"写回前核对 blobs"。
5. **缺失内容的路径不写回并在残留清单标注"内容缺失"。** 同第 4 条，断言残留清单里的原因是"内容缺失"。守的是"缺失内容标注"。
6. **存在其它外部改动时默认拒绝。** 在有效状态里对某路径写 `content_stored = 1` 的条目，磁盘上该路径存在且哈希与目标不一致，调用 `align`（`force = false`），断言返回 `AlignRefusedExternal` 错误、磁盘不变。守的是"存在外部改动默认拒绝"。
7. **显式强制时覆盖外部改动。** 同第 6 条，调用 `align`（`force = true`），断言该路径被覆盖为目标内容、磁盘哈希等于目标哈希。守的是"force 覆盖"。
8. **回滚目标是链上某个快照的有效状态，需要先沿链折叠。** 创建基线加若干增量，目标是最老增量，调用 `align`，断言对齐的是基线到目标的折叠结果（不是目标快照自己的清单）。守的是"沿链折叠"。
9. **跨工作区对齐被拒。** 在工作区 A 创建快照，用工作区 B 的作用域对齐，断言返回 `UnknownSnapshot`。守的是"快照的 workspace_id 必须等于作用域的工作区"。
10. **空有效状态允许。** 对齐一个空有效状态的快照，断言成功、残留清单为空、磁盘不变。守的是"空清单合法"。

第 1、2、3 条合起来守的是同一件事：范围与超阈值的区分。第 4、5 条守的是 blobs 核对与"内容缺失"标注。第 6、7 条守的是外部改动检测与 `force` 覆盖。第 8 条守的是沿链折叠。第 9、10 条守的是跨工作区校验与空清单合法性。

## 七、风险：容易做成测试通过但语义错的地方

| 风险 | 为什么测试会照样通过 | 对策 |

## 八、已裁决的分歧点

三处分歧点已由主 Agent 裁决，全部采纳 Explorer 的建议（均选甲）：范围是参数而不是存储层自己算的（存储层不解析工具清单，范围由调用方从清单读出后传入，乙让存储层依赖工具清单违反分层）；折叠算法提取为共享模块而不是在 `align.rs` 里重复一份（06.7 与 06.8 共用折叠，重复一份会让"同一套折叠算法"失效，且 squash 与 align 的折叠顺序必须一致）；外部改动检测是"磁盘与目标哈希不一致"而不是"差异不由已记录工具调用产生"（存储层没有事件日志，只能检查前者，后者由调用方用事件日志判断）。裁决理由见下表"建议"列。

| 分歧 | 两种做法 | 建议（已裁决采纳） |
|---|---|---|
| 范围的来源 | 甲：范围是参数，存储层不解析工具清单。乙：存储层自己解析工具清单算范围 | **建议选甲。** 理由见第二节。存储层不解析工具清单，范围由调用方（server/执行器）从清单读出后传入。乙让存储层依赖工具清单，违反分层 |
| 折叠算法的位置 | 甲：提取为共享模块（`fold.rs` 或放进 `entries.rs`），squash 与 align 共同调用。乙：在 `align.rs` 里重复一份折叠 | **建议选甲。** 理由见第二节。06.7 与 06.8 共用折叠，重复一份会让"同一套折叠算法"失效，且 squash 与 align 的折叠顺序必须一致 |
| 外部改动检测的判据 | 甲：存储层检查"磁盘与目标哈希不一致"，报告差异、默认拒绝。乙：存储层检查"差异不由已记录工具调用产生"，需要事件日志 | **建议选甲。** 理由见第二节。存储层没有事件日志，只能检查"磁盘与目标哈希不一致"。"差异不由已记录工具调用产生"由调用方用事件日志判断 |

### 10.1 表结构核对：全部成立

`0002_content.sql` 的 `snapshots` 与 `snapshot_entries` 表与计划第二节所写逐列一致。`snapshots` 的主键是 `id`，`workspace_id` 有外键，`seq` 与 `workspace_id` 组成唯一索引，`parent_id` 是无动作自引用外键，`kind` 有取值域 CHECK，重定基线留痕三列有 CHECK。`snapshot_entries` 的主键是 `(snapshot_id, path)`，`kind` 有取值域 CHECK，形态 CHECK 已定形（06.2.1.1 补强），`content_stored` 不给默认值。`workspaces` 表有 `root_path` 列，对齐以它为根。

### 10.2 句柄形状核对：`conn_mut` 已就位

### 10.3 06.6 读路径核对：对齐的公共依赖

### 10.4 四处补强

**第一，`workspaces.root_path` 是工作区磁盘根路径，对齐以它为根。** `0001_core.sql` 的 `workspaces` 表有 `root_path` 列，存储层从它读出工作区磁盘根路径，对齐以它为根扫描。这条与 06.5 的 CAS 根目录（数据库文件同级的 `blobs` 目录）同型：存储层自包含，根路径由存储层从库里读出，不由调用方给。

**第二，`content_stored = 0` 的条目必须带 `mtime`，残留清单靠它判断文件在快照之后动过没有。** `0002_content.sql` 的形态 CHECK 已强制"未存内容必带修改时间"。06.8 的残留清单靠 `mtime` 判断文件在快照之后动过没有，缺 `mtime` 的超阈值条目在写入路径就被拒。这条与 06.6 的写入路径断言同型。

**第三，折叠算法是 06.7 与 06.8 的公共依赖，应提取为共享模块。** 06.7 的 squash 在 `squash.rs`，06.8 的对齐在 `align.rs`。两者共用折叠，因此折叠算法应提取为共享模块（如 `fold.rs` 或放进 `entries.rs`），由 squash 与 align 共同调用。06.7 在进行中，折叠可能在 `squash.rs`，06.8 应把它提取为共享模块。这条与 06.6 把读路径收进本批的裁决同型：折叠是验证对齐的前提（读回有效状态断言等于对齐状态），也是 06.7 与 06.8 的公共依赖。

**第四，对齐读有效状态、对齐磁盘、输出残留清单，是第三种独立职责。** 06.6 的 `create_snapshot` 只按链追加，06.7 的 squash 改写链，06.8 的对齐是第三种独立职责：读有效状态、对齐磁盘、输出残留清单。这条职责分离是"这一批只有一个目的"的前提，不靠调用方记得"对齐是独立的"。
