# 解析输入与预算审查

提交 `830a815` 新增 `context/{budget,input}.rs`，默认预算确实通过第 4 条校验，千分比整数也比浮点稳；但帧重叠只比较相邻帧的首尾，完全包含的情况会漏过，`fixed_layer` 只带指纹不带内容，04.4 拼不出固定层那一段。

1. 第 4 条校验与默认值（`budget.rs:127` 至 `:133`、`:177` 至 `:179`、`:198`、`:245` 至 `:246`）。触发点为 200000 乘 850 除 1000 等于 170000，剩余 30000 不小于 20000，默认值通过，测试断言的正是 170000 与 30000，与推理一致，不会拒掉 85% 下的常规配置。`reserve == headroom` 也能通过（`:128` 用严格大于），但无用例固定这个边界；`:210` 至 `:213` 只覆盖 reserve 20 对 headroom 15 的微小配置。`:124` 的 `reserve >= limit` 只在触发点为零时才有独立作用（如上限 100、千分比 1，余量等于上限，预留等于上限会被它拦下），注释应写明它是兜住"余量等于上限"这一格的边界，否则读者会以为它与下一条重复。
2. 千分比整数（`budget.rs:15` 至 `:19`、`:146`）。决策正确，理由有一半站不住：IEEE-754 的四则运算本身跨平台确定，真正不稳的是 0.85 无法精确表示、配置序列化往返与 170000 附近的相等判断；而向下取整最多只差不足一个抽象计数，对 20000 的预留没有量级意义，兜住压缩请求的是 `compress_reserve` 留出的 30000，不是取整方向。注释应改成"配置能精确表达 85%，避免边界比较歧义"。
3. 与 0018 第一节的偏差（`input.rs:33`、`:38` 至 `:40`、`:44`、`:138` 至 `:140`）。`fixed_layer` 是 `Node` 而非 ADR 写的固定层内容，而 `NodeBody::FixedLayer` 只有 fingerprint（`node.rs:40` 至 `:43`），04.4 因此拿不到系统提示、工具目录、AGENTS.md 正文，第一段无内容可拼；`recent` 用 `Vec<Node>` 而 ADR 写 `Vec<NodeId>`，注释还留着"每项是（节点，轮次节点 id）"的元组说法，与字段类型不符；`checkpoint_facts` 用 `Vec` 而非 `Map`，重复键不校验，`facts()` 取第一条，措辞依赖插入顺序；ADR 里的 `head` 也不在结构中。放节点而非 id 有理由（解析不能查库），但偏差与补偿需要写进新 ADR 或 detail，否则 04.4 会按 ADR 去取内容。`current`（`:41` 至 `:42`）同样不校验帧与固定层，与 `recent` 的检查不对称。
4. 帧重叠检查（`input.rs:120` 至 `:127`、`:52`、`:241`）。只比较前一帧的末节点与后一帧的首节点，等价于只抓"共享一个边界节点"这一种。帧 A 覆盖 1 和 2、帧 B 覆盖 1 和 3 时，2 不等于 1，通过；A 覆盖 1、2、3 而 B 覆盖 2 时，3 不等于 2，也通过；非相邻帧重叠与 `covers` 为空（`if let` 直接跳过）同样不报。`:52` 的注释写"后一个帧的开始早于前一个帧的结束"，比实现宽，`:95` 的"帧之间不重叠"这一验收口径不成立，用例正好落在唯一被抓的那一格。改法是把全部 `covers` 的节点灌进一个集合，插入时发现重复即报，包含、非相邻与空帧一并覆盖。
5. 不可达与事实条目（`input.rs:57` 至 `:61`、`:108` 至 `:114`）。不冲突。0018 第二节的四行要靠 `reachable` 与 `disk_matches` 才能选中，"不可达"在第三、四行仍需事实条目区分方向，所以强制补齐正是让四行表保持完备的机制；而"事实缺失"没有第五行，拒绝输入比发明措辞正确。真正的缺口是 `Frame.checkpoint` 为 `None` 时既无事实也无措辞（`node.rs:96`），0018 没有这一格，04.5 会再次被迫自行发明，应由 04.3 或 04.5 先裁定。
6. 单位混用（`budget.rs:3` 至 `:5`、`:22` 至 `:25`、`:81`）。模块注释声明整个结构用抽象计数，但 `preview_bytes` 是字节、`keep_recent_turns` 是轮数，三种单位共处一个结构而注释只写了一种。后果是任何把 `preview_bytes` 与 `limit` 相减或比较的调用点都是单位错误，且 `Budget::new` 完全不校验它，零值与大于上限都放过。`:81` 说值来自 0018 参数表，而 5120 恰好等于表中"事件正文预览"那一行的头 4 KiB 加尾 1 KiB，但那一行讲的是事件正文，解析预览长度在表里没有单独的值，出处由此不可引用。建议字段改名带单位后缀，并在模块注释里列出三种单位，或把它移出 `Budget`。

需要复核的信号：04.4 直接读 `fixed_layer` 拼第一段时，会先撞上第 3 条的内容缺失，而不是遇到编译错误。
