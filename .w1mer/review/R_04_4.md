# 四段解析审查

提交 `fbdbf8b` 新增 `resolve` 与四段输出，段顺序与固定层正文都正确，函数体也确实没有排序、哈希表或环境读取；但错放段位的节点会被静默丢弃，段标签按节点类型而非所在段给出，字节用量又被当作抽象计数使用，三处都会在调用方出错时安静地产出一个"合法"结果。

1. 纯函数承诺成立（`resolve.rs:141` 至 `:192`）。函数体没有排序、没有哈希表（`BTreeSet` 只出现在 `resolve.rs:405` 的测试里）、没有 IO，`format!` 走 `Display` 且不随 locale 变化。`frames` 与 `recent` 的顺序全由输入决定，`validate` 又保证帧两两不共享节点（`input.rs:123` 至 `:128`），因此同一输入两次调用必然逐字节相同。唯一可改变语义的是 `checkpoint_facts` 的重复键：`facts()`（`input.rs:139` 至 `:141`）取首条命中而 `validate` 不校验唯一性，语义相同但顺序不同的两份输入会给出不同的漂移措辞。
2. 三段为空时输出仍合法，不会产出零条消息（`resolve.rs:147` 至 `:154`、`input.rs:106` 至 `:108`）。固定层先过 `NotFixedLayer` 校验，所以 `frames`、`recent`、`current` 全空时恰好一条系统消息，用量等于固定层字节数。退化点在空待办与空摘要：`Todo { items: [] }` 产出"当前待办："加一个空行（`resolve.rs:230` 至 `:237`），空摘要帧产出空正文消息，两者都无校验，模型会收到只有标签没有内容的一条。
3. 静默丢内容（`resolve.rs:204` 至 `:206`、`input.rs:116` 至 `:120`）。`node_to_message` 对帧与固定层返回 `None`，而校验只检查 `recent`、不检查 `current`。调用方把帧或固定层节点错放进 `current`，该节点就从消息数组里无声消失，既不报错也没有用例；这违反"回退与压缩只是改变输入"，且错误方向是丢内容而不是多内容。
4. 段标签由节点类型决定，不由所在段决定（`resolve.rs:207` 至 `:238`）。`Notice` 一律标 `Current`，`Turn` 与工具消息一律标 `Recent`。一条几轮之前的"文件已更新"通知若按 0003 的读集设计放进 `recent`，数组顺序仍然正确，但 `segment` 说它在当前段；今天只有诊断与测试读这个字段，而 05 的压缩要按段数"最近三轮"，按 `Segment` 切片会数错。正确做法是把段参数传给 `node_to_message`。
5. 用量单位混用（`resolve.rs:116` 至 `:119`、`:190`，`budget.rs:14` 至 `:19`）。`estimated_usage` 是字节，`Budget::limit` 与 `should_compress` 是抽象计数。中文正文每字三字节，直接送进 `should_compress` 会在真实用量约三分之一时就判为 85%，压缩大幅提前；纯 ASCII 又反向低估。字段注释说"调用方可以换成自己的分词计数"，但数值在返回时已经算定，调用方换不掉。`用量是正文总字节数`（`resolve.rs:427` 至 `:432`）用与实现完全相同的表达式复算，只能证明代码没被改，不能证明单位是字节而非字符，应断言字面量并补一条中文用例。
6. 空覆盖帧没有把关（`resolve.rs:195` 至 `:201`、`input.rs:123` 至 `:125`）。校验对 `covers` 为空的帧直接跳过重叠检查，`frame_text` 随即退化成纯摘要，"帧必须覆盖一段历史"这条没有任何机制承接；压缩若产出空覆盖帧，历史无声消失，解析结果看起来完全合法。要么在校验里拒绝空 `covers`，要么让 `frame_text` 明说覆盖范围未知。
7. 漂移缺口与不可达分支（`resolve.rs:163` 至 `:173`、`input.rs:109` 至 `:115`）。校验已强制"帧引用检查点必须有事实"，所以 `&& let Some(facts)` 的跳过分支不可达，真出问题时会静默而不是显式失败或注释说明；同时 `drift` 只为带检查点的帧记账，长度与 `frames` 不对应，调用方无法按下标对齐。帧无检查点时 0018 没有对应措辞（04.3 已指出），本批次仍未裁定，模型于是不知道"这段摘要背后没有快照"。
8. 可复现性测试只覆盖同一引用连调两次（`resolve.rs:321` 至 `:327`、`:369` 至 `:385`）。缺三类：重复检查点键导致措辞随输入顺序变化、三段全空的边界、多帧时 `drift` 顺序与消息交错顺序。现有用例最多只放一个帧，`resolve.rs:157` 至 `:174` 的双帧交错路径从未被执行。

需要复核的信号：05 的压缩一旦按 `Segment` 切片数最近三轮，第 4 条会以"少数一轮"的形式暴露，而不是编译错误。
