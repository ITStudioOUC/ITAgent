# 单二进制分发审查

Status: issues

## 结论

提交 `ede76a8` 落地 `ita` 单二进制角色分发与 ita-worker 空壳，验收三条全部达成，CI 的 `--no-tests=pass` 已删除且文档同步。遗留问题集中在接口注释与测试覆盖，运行逻辑本身无错。本角色只读，未跑 cargo；源码内共六项测试，"全绿"只能由实现者的自测记录背书，本次未实证。

## 逐项

- 缺省 master（`crates/ita-cli/src/role.rs:27`）：逻辑合理，但 master 落地后误敲 `ita` 会静默起 server 并占住数据库，而这条选择在仓库里只出现在 `01_plan-02.md:17` 的验收表格，没有 ADR 承接。
- 未知角色退出 2（`crates/ita-cli/src/main.rs:23`）：符合用法错误用 2、执行失败用 1 的通行约定，与验收口径一致，仓库内无第二套退出码约定，不必改。
- 中文测试名（`role.rs:49` 至 `:61`、`tests/cli.rs:10` 至 `:26`）：可接受，Rust 支持非 ASCII 标识符，nextest 与 `-E 'test~...'` 过滤均无额外代价；长期沿用则应写进 `CONVENTIONS.md` 而非只靠示范。
- `--version` 版本源（`main.rs:17`）：一致。`crates/ita-cli/Cargo.toml:4` 继承根 `Cargo.toml:18` 的 0.1.6，`Cargo.lock` 十一个成员条目同为 0.1.6，`env!("CARGO_PKG_VERSION")` 恒等于根版本。
- 未实现却退出 0（`main.rs:28` 至 `:32`）：满足验收但会误导脚本，把 0 当作"服务已就绪"继续执行；`tests/cli.rs:18` 只断言状态码，删掉 `eprintln!` 测试仍过。
- worker 的 `run()`（`crates/ita-worker/src/lib.rs:9` 至 `:23`）：注释写"接受已建立的会话连接"，签名是 `pub fn run() {}`，两者对不上；空实现不构成假象，当前无调用方。
- 无状态约束（`lib.rs:22`）：与 AGENTS.md 单写者不变量和 ADR 0001 第 16 至 18 行一致，但只是注释，往 `crates/ita-worker/Cargo.toml` 加 `rusqlite` 无一门会失败；内核侧有 `check_kernel_purity.sh` 承接同类约束，worker 侧缺对应一步。
- 测试覆盖（`tests/cli.rs:9` 至 `:30`）：验收三条各有断言，缺 `-V` 短选项与无参数启动两例；`cli.rs:14` 用测试 crate 自身的 `CARGO_PKG_VERSION` 作期望，版本号漏推时仍通过。
- 空测试集（`.github/workflows/ci.yml:70`）：已删除 `--no-tests=pass`，`STACK.md:7` 与 `19_plan-02-3.md:18` 同步改为默认语义，`grep no-tests` 仅剩这两处说明，与 yml 一致。

## 问题

1. `crates/ita-worker/src/lib.rs:9` 的接口注释与签名不符，改为"入口占位，协议落地后接收会话连接"，或等真有连接参数再写这句。
2. `crates/ita-cli/tests/cli.rs` 补三例：`-V` 与 `--version` 输出相同、无参数按缺省角色执行、三个角色的"尚未实现"必须出现在 stderr 且退出 0；最后一例把过渡态固化下来，真实现时测试会提醒改。
3. 缺省 master 与未实现退出 0 是隐性契约，唯一记录处是 `01_plan-02.md:17` 的验收表格；02.7 做文档同步时应写进 `STRUCTURE.md` 的 ita-cli 条目或单开一份 ADR。
4. worker 的无状态约束无人守，建议仿内核纯净门加依赖断言，或在 02.7 明确记为已知空洞，二选一，不留白。
