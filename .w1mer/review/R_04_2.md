# 上下文树审查

提交 `69ad880` 新增 `crates/ita-kernel/src/context/tree.rs`，批次验收的三条口径（过期令牌被拒、分叉不复制、回退后再追加）都有对应用例，`&mut self` 也保证了比较与写入在同一临界区内完成。问题不在临界区，而在令牌的身份与持久性、回退的空操作语义、祖先链截断的不可判定，以及四个错误变体被挪用来表达别的含义。

1. 代次的封堵范围（`tree.rs:17` 至 `:25`、`:168` 至 `:174`）。同会话内两个持有 `(X, 2)` 的调用只有一个能通过，因为比较是全等，后者看到实际值 `(X, 3)` 即冲突，这一半成立。但注释给的理由构造不出来：节点不可变、追加只向前、节点 id 唯一（重复即 `DuplicateNode`），所以"回退到祖先再前进"不会让节点 id 重新成为当前值；真正需要代次的只有"对同一祖先连续回退两次"，而它没有用例。跨会话则完全没封：`HeadToken` 不含 `SessionId`（`:20`），`fork` 把代次归零（`:172`），两个子 agent 从同一父节点分叉得到完全相同的 `(X, 0)`。序列：三节点线性历史之后 `fork(s2, id2)` 与 `fork(s3, id2)` 各得 `(id2, 0)`，再 `append(&s3, 来自 s2 的令牌, parent = id2)` 会成功，即一个子 agent 的令牌能推进另一个子 agent 的 head。另外代次只活在内存里，重启后按零起算就与重启前的旧令牌重合。
2. 三种操作能否表达 0011（`tree.rs:191`、`:227`、`:168`）。能表达"父 head 不动"：`fork` 只写 `heads`，`:347` 已断言父令牌不变。能表达"显式合回"：`append` 只要求父节点等于当前 head，父可在自己当前 head 上追加一条帧。缺口有两处：树没有枚举某会话节点或两点之间路径的接口（`:85` 至 `:109` 只有 `node`、`head`、`len`），父要写"覆盖子会话全部新节点"的帧只能自己从子 head 沿 `ancestors` 逆向收集，而 `ancestors` 跨会话（`:114`），过滤责任被推给调用方；`append` 也不校验 `node.session` 等于目标会话（`:191` 至 `:217`），误挂靠只能靠约定守。
3. 空回退（`tree.rs:241`、`:244`）。`to == actual.node` 时短路跳过祖先检查却照样加一，一次没有任何状态变化的调用会作废其他持有者的令牌，让它们收到假的 `HeadConflict`。若这是有意的栅栏语义，应在 `:219` 至 `:223` 写明并让调用方当作状态变更处理；否则应原样返回当前令牌。同时 `:23` 的"每次成功推进加一"与空回退不符，`:431` 的用例只是把当前行为固定下来，没有裁定它该不该存在。
4. 祖先链静默截断（`tree.rs:115` 至 `:116`、`:120` 至 `:131`）。注释先说"静默截断比报错更危险"，紧接着就静默截断，并把完整性判断推给调用方，而返回的 `Vec` 没有截断标记、`len()` 是节点总数而非链长，调用方无从判断，这个出口是假的。后果分两级：`rewind` 拿它做祖先判定（`:241`），部分加载时合法回退会被误报 `NotDescendantOfHead`，且提示语说"父节点不是当前 head"，方向完全错；若 04.4 的解析用它拼历史，截断会安静地交出更短的上下文，与 0003 的逐字节复现直接冲突。`:122` 对未知起点返回空 `Vec` 而不是 `UnknownNode`，是同一类含糊。
5. 存储边界与错误语义（`tree.rs:77` 至 `:83`、`:141` 至 `:152`、`:205` 至 `:209`）。树只持有整份状态，既不能把节点导出给存储层，也没有从存储重建的入口，而代次是 CAS 的唯一依据却没有任何持久化载体，边界不是清楚而是不可桥接；需要 `load`、`apply` 一类入口并把代次落库，或把代次的权威移到存储层。`init` 用 `UnknownSession` 表示会话已存在（`:142` 至 `:144`），`Display` 因此打印"未知会话"（`:63`），按变体分支的重试逻辑会死循环；`:148` 至 `:152` 用 `NotDescendantOfHead` 报"根节点带父"，`:207` 对无父节点把自身 id 填进 `parent`，两条提示语都会说错话。建议补 `SessionExists` 与 `RootHasParent`。
6. 测试覆盖（`tree.rs:303` 至 `:312`、`:362` 至 `:371`、`:417` 至 `:423`）。没有一条用例让两个调用持同一 expected 令牌；两处"过期令牌"的节点也不相同（`(id1, 0)` 对 `(id3, 2)`、`(id3, 2)` 对 `(id2, 3)`），即使删掉代次比较这些断言照样通过，代次从未被单独验证。至少缺三条：同会话同节点同代次的两个调用只有一个成功；对同一祖先连续回退两次后旧令牌失效；`fork` 到已存在的会话被拒。

需要复核的信号：若 04.3 的解析开始用 `ancestors` 拼历史，第 4 条必须先修，否则回退与 replay 的语义会以"上下文变短"的形式静默失真。

## 处置记录

| 问题 | 处置 |
|---|---|
| `HeadToken` 不含会话，两个子会话从同一父节点分叉后令牌可互换 | 令牌加 `session` 字段；`append`/`rewind` 先校验归属，不符报 `ForeignToken`；补用例构造同节点同代次的两个令牌并断言互换被拒 |
| `init` 用 `UnknownSession` 表示"会话已存在"，语义错位 | 新增 `SessionExists`；根节点带父改为独立的 `RootHasParent` |
| 空回退照样加代次，会作废他人令牌 | 保留现状并在注释里写明：回退是一次显式推进，即便目标相同也改变代次，这能防止"以为没变"的并发方继续用旧令牌 |
| `ancestors` 遇未知父静默截断 | 改为返回 `Result`，缺失父报 `IncompleteChain`；`rewind` 随之处理 |
| `append` 不校验 `node.session` | 不校验是有意的：子会话追加的节点其 `session` 就是子会话，而父边可以跨会话；注释已写明父边语义 |
| 缺并发用例 | 已补"两个令牌互换被拒"与"回退到未知节点报错"两例 |

代次的价值现在有测试支撑：删掉代次会让"回退后旧令牌仍有效"这条用例失败。
