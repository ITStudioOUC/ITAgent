## 逐项判断

- **零依赖成立，但它不等于内核纯。** `crates/ita-kernel/Cargo.toml:9` 的依赖表为空且没有 dev 与
  build 依赖，`Cargo.lock:5` 到 `:7` 只列一个包，两处互证，`cargo tree -p ita-kernel` 只能剩自身。
  但 ADR 0001 第 12 至 13 行禁止的还有 `std::time`，它无需依赖即可 import，故本条验收只排除第三方
  依赖，真正的判据在 02.2 的 clippy 配置与检查脚本。
- **版本格式与继承合规。** `Cargo.toml:6` 为 `0.1.0`，落在 0.N.P 内，与"基线 0.1.0 锚在 ROADMAP
  02"一致；`crates/ita-kernel/Cargo.toml:4` 到 `:7` 用 `version.workspace` 等四项继承，没有各写
  一份。`Cargo.toml:10` 的 repository 未被继承，本项目不发布 crate，无功能影响。
- **两条 lint 不与后续批次冲突。** `crates/ita-kernel/src/lib.rs:11` 的 `forbid(unsafe_code)` 对内
  核成立，因为 landlock 与 seccomp 在 ita-sandbox、进程操作在 ita-exec；代价是它不可局部豁免，
  第三方过程宏若在展开里生成 unsafe 会直接编译失败，届时只能改文档降为 deny。真正的风险是模板
  扩散：02.4 与 02.5 建空壳时不要复制这一行，否则沙箱的 FFI 会被封住且无法就地开放。`lib.rs:12`
  的 `deny(missing_docs)` 与 AGENTS.md 第 5 节同向，成本是公开变体与字段各需一行注释，且可按项
  allow，不会卡住后续批次。
- **没有 IO 或时钟依赖的夹带。** 提交里没有 build.rs 与 `.cargo/config`，`crates/` 下搜不到
  `std::`、tokio、rusqlite、reqwest 与 rand 的引用。
- **提交信息合规。** 主题有合法 type，无 scope 前缀、任务号、哈希与测试计数，无 `｜` 分隔，长度在
  60 字内，未命中私有词汇，写的是改了什么而不是实现步骤。

## 待跟进与风险

- `crates/ita-kernel/src/lib.rs:5` 到 `:6` 声称边界"由依赖检查与 lint 共同强制"，两道门目前都不
  存在，02.2 交付前不应据此认为纯度已被强制；若脚本只查 Cargo.toml 而不查 `std::` 的使用，
  `std::time::Instant::now()` 会一路通过到实现期。
- `.w1mer/codebase/STACK.md:7` 把命令写成 `cargo nextest run -p <crate> --no-tests=pass`，空测试集
  算通过；本批次内核没有测试，这样写现在合理，建议 02.3 的 CI 出现测试后改用不带该参数或
  `--no-tests=fail`，否则"测试被整体删掉"与"从未写过测试"都无法被发现。
- 工具链写 `stable` 而非具体版本，MSRV 声明 1.85 却无法复现同一次构建，宜在 CI 里给一份带具体
  版本的工具链矩阵。
