## Findings

### 提交一：锁文件同步（fa8ddf9）

`Cargo.lock` 的 ita-proto 条目补上 `dependencies = ["ita-kernel"]` 一行，其余不动。正确性从不变的一侧推导：清单 `crates/ita-proto/Cargo.toml` 在 08.1 的实现提交 5943ecb 里加了 `ita-kernel = { path = "../ita-kernel" }`，那一提交只动了清单、没动锁文件，锁文件里 ita-proto 条目没有依赖列表，CI 的 `--locked` 会因清单与锁文件不一致而失败。本提交正是补上这一行，锁文件与清单恢复一致。ita-kernel 是工作区成员（路径依赖），锁文件条目按名记录、不带版本与来源，与 ita-store 既有的 ita-kernel 依赖记录同型。核对端点锁文件：ita-proto 条目依赖列表恰为 ita-kernel 一项，与清单的单一依赖相符，没有多记也没有漏记。提交信息「chore: 同步锁文件记录 ita-proto 对 ita-kernel 的依赖」类型 chore、中文一句话、无 scope 前缀、无内部编号，符合第 3 节。

### 提交二：版本推进（1c82af2）

`Cargo.toml` 的 `[workspace.package] version` 从 0.1.45 改为 0.2.0，`Cargo.lock` 的十一个本地成员同步从 0.1.45 改为 0.2.0。核对第 4 节：08.1 是史诗 08 的首个批次，08 是 ROADMAP 顶层行，属新史诗，推进走 epic 模式，N 加一且 P 归零，0.1.45 推出 0.2.0，与脚本 `bump_version.sh epic` 的行为（n 加一、p 归零、同步锁文件里全部无 source 行的本地成员）一致。核对端点：根清单版本 0.2.0，锁文件十一个成员（ita-cli、ita-exec、ita-kernel、ita-model、ita-proto、ita-sandbox、ita-server、ita-store、ita-tools、ita-worker、ita-workflow）全部 0.2.0，数量与工作区成员数一致，没有漏刷。提交信息「chore: 推进版本到 0.2.0」版本号用阿拉伯数字，符合第 4 节末条。本批只有一个版本推进，批次内多个提交共用同一版本号，也符合「一个批次只推进一次」。

### 提交三：勘察计划归档（525e67e）

`.w1mer/detail/33_批次_08_2_本地_socket_与连接级工作区绑定的执行计划.md` 的六处修订，把 08.2 的勘察计划与 08.1 实际已提交的代码对齐。逐条核对端点文件 `crates/ita-proto/src/envelope.rs` 与 `version.rs`：`Response` 是 stdout、stderr、exit_code 三字段，`HandlerError` 是 PolicyDenied、LeaseDenied、Failed 三变体，`Invocation` 是 version、caller、session、cwd、argv、stdin、lease_id 七字段且无 workspace，`Handler` trait 签名是 `fn handle(&self, invocation: Invocation) -> Result<Response, HandlerError>`，`ProtocolVersion` 是名义类型且带 `new(major)` 与 `major()`，`SupportedRange` 构造期校验下限不大于上限，`negotiate` 是纯函数，`CURRENT_PROTOCOL_VERSION` 是版本 1，`DEFAULT_SUPPORTED_RANGE` 只接受当前版本——全部与代码相符。文档引用的两个实现提交 5943ecb 与 bcb2176 均存在且内容对口。新增的「Store 句柄不是 Send」段落核对 `crates/ita-store/src/db.rs`：Store 持有 rusqlite 的 Connection，该类型不是 Send，握手因此在主线程做、连接线程只收 WorkspaceScope，推断成立。分层门允许表核对 `check_layers.sh`：ita-proto 允许 ita-kernel 与 ita-model，ita-server 允许六个登记项，文档转述与脚本一致。提交信息「docs: 归档本地 socket 与连接级工作区绑定的勘察计划」类型 docs、中文一句话，符合第 3 节。

### 架构影响注记

- 锁文件契约：ita-proto 对 ita-kernel 的依赖边在锁文件里补齐，与清单一致，CI 的 `--locked` 门恢复通过。这条依赖边本身是 08.1 实现的产出（信封的 argv 是内核的命令 AST，会话与租约标识符是内核的名义类型），本提交只是把锁文件对齐到清单，没有新增依赖关系。
- 版本号：工作区版本从 0.1.45 推进到 0.2.0，史诗计数器从 1 进到 2、批次计数器归零，十一个本地成员的锁文件条目同步。08.2 及后续批次在此基础上继续推进批次计数器。
- 勘察计划归档：08.2 的执行计划（detail 33）落盘并修订，对 08.1 产出类型的描述与已提交代码对齐，08.2 实现者消费的是核对过的计划，不重新实现信封与版本协商。
- 未动的契约：信封与版本协商的全部代码（envelope.rs、version.rs、lib.rs）与清单均未在本批改动，本批只动锁文件、版本与勘察文档。

### 非阻塞观察
