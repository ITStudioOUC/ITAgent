# Review R_06_4

Status: ok

## Conclusion

06.4 的三个检查点（heads.rs、commit.rs、db.rs 的两个新错误变体与 lib.rs 接线、tests/commit.rs 九条集成测试）全部按已提交代码复核通过，正确性从不变侧推导，不依赖改动代码自证。帧正文用长度前缀文本写进 `nodes.inline_body`，四个字段全部可逆，没有引入 `serde_json`、没有新增迁移，`prompt_version` 不进帧节点；head 的比较并交换是一条 `UPDATE` 同时匹配 `(head_node, head_generation)`，影响行数为零即冲突，代次不符的 ABA 情形被拒；事务内顺序是插入帧节点、比较并交换、追加事件，事件追加排在比较并交换成功之后，冲突不烧 seq；跨工作区校验在事务内用 `SELECT EXISTS` 断言会话、父节点、覆盖列表三个位置，检查点不校验。九条验收标准每条都写成独立的测试函数且通过。无阻塞问题。

## Findings

- **帧正文编码：长度前缀文本，可逆，不引入依赖，不新增迁移（第 7 条）**：`commit.rs` 的 `encode_frame` 按"摘要长度前缀加冒号、覆盖计数、每个 26 字节 id 加换行、检查点存在标志加可选 id、指纹长度前缀加冒号"的布局拼串，`decode_frame` 按长度精确取字节还原。摘要与指纹是自由文本、可含换行，读方按字节长度取，换行不构成歧义，`summary_with_newlines_and_colons_round_trips` 守住这条。`nodes` 表没有为帧单列字段，编码走 `inline_body`（TEXT 列），`body_hash` 与 `body_len` 对帧节点恒为 NULL，与 ADR 0018 的 4 KiB 散文上限一致，帧正文有界。`Cargo.toml` 的依赖表只有 `ita-kernel`、`rusqlite`、`ulid` 三项，没有 `serde_json`；`migrations/` 两份脚本一字未动，迁移版本仍是 2。`prompt_version` 不进帧节点：内核 `Frame` 结构只有 `summary`、`covers`、`checkpoint`、`fixed_layer_fingerprint` 四个字段（`node.rs` 已定型），`CommitPlan` 的 `prompt_version` 属于压缩调用事件，落库推迟到 06.5 之后能写内容寻址引用时，与计划第八节的裁决一致。
- **head CAS：一条 UPDATE 同时匹配节点与代次，ABA 被拒（第 2、3 条）**：`heads.rs` 的 `compare_and_swap` 执行 `UPDATE sessions SET head_node = ?2, head_generation = head_generation + 1 WHERE id = ?1 AND head_node = ?3 AND head_generation = ?4`，影响行数为零即冲突。只比节点不比对代次的实现，第 3 条测试会把 `head_generation` 手动改成 3 再提交期望代次 1 的帧，CAS 会返回 1 行、测试断言 `HeadConflict` 失败，因此这条测试能把"丢代次"的实现暴露出来。`compare_and_swap_conflicts_on_generation_mismatch` 模块内单测与它同守。代次加一由 `head_generation = head_generation + 1` 完成，与内核 `Tree::append` 的语义一致，落库版本没有把代次丢掉。
- **事务内顺序：插入帧节点、CAS、追加事件，冲突不烧 seq（第 9 条）**：`commit_in` 先校验三个位置，再 `INSERT INTO nodes`，然后 `compare_and_swap`，影响行数为零时返回 `HeadConflict`，事务回滚，帧节点行不落库、head 不动、seq 不消耗；只有 CAS 成功才走 `events::append_in`。`conflict_does_not_append_event` 断言冲突后 `events` 表无新增行、`workspace_seq.next_seq` 与调用前相等。若实现把事件追加排在 CAS 之前，冲突时事件行已写入、seq 已消耗，回滚虽能撤销事件行，但"计数器保持原值"这条验收会失败。第 2、3、9 条合起来覆盖"冲突不写帧行、不动 head、不烧 seq、不追加事件"四个可观察量。
- **跨工作区校验：会话、父节点、覆盖列表三个位置，检查点不校验（第 4、5、6 条）**：`commit_in` 在事务内用 `SELECT EXISTS(... AND workspace_id = ?2)` 依次断言会话、父节点、覆盖列表里每个节点都同属作用域的工作区，任何一条失败即返回 `CrossWorkspace` 并回滚。检查点是弱引用，允许悬空，不校验，与 ADR 0003 的决策一致。三条测试分别把会话、父节点、覆盖列表指向另一工作区的 id，断言返回 `CrossWorkspace`、帧节点行不落库、seq 不变。`nodes` 与 `sessions` 的 `workspace_id` 外键只保证引用的工作区存在，不保证引用的节点属于当前作用域，这条校验由写入路径承接，表结构拦不住。
- **九条验收标准每条都写成测试且通过**：`tests/commit.rs` 有 9 个 `#[test]` 函数，与计划第四节的九条验收一一对应。第 1 条断言成功提交后 `body_kind` 是 `'frame'`、`parent_id` 是 X、`head_node` 是帧节点、`head_generation` 是 2、seq 加一；第 8 条用同一个节点 id 提交两次，第二次断言返回 `StoreError::Sqlite`（重复节点错误）、head 不动、seq 只消耗一次。每个测试走公开接口 `commit_frame`，不自己拼 SQL 写帧行（只用 `conn_for_test` 读回断言与制造 ABA 情形）。实现者提交前已自测，nextest 每测试独立进程，无共享全局状态依赖。
- **read_head 打了 #[allow(dead_code)]，它是原语的一部分**：`heads.rs` 的 `read_head` 读会话当前的 head 令牌，本批只接线帧提交，帧提交路径不读回 head，因此 `read_head` 在非测试构建里无调用点，`#[allow(dead_code)]` 是必要的。计划第五节的文件清单明确 heads.rs 要提供"读当前 head 令牌、执行 CAS UPDATE"两个原语，`read_head` 是回退（后续批次）与事件读路径的消费者，本批不接线是计划明示的，不是遗漏。`compare_and_swap` 是 `pub(crate)`，只被 `commit.rs` 的 `commit_in` 调用，`heads` 模块在 `lib.rs` 里是 `mod heads`（私有），不对外暴露，与"帧提交是它的一个消费者，回退是另一个"的通用原语定位一致。
- **db.rs 加两个错误变体，lib.rs 接线**：`StoreError` 新增 `HeadConflict` 与 `CrossWorkspace(String)` 两个变体，`Display` 实现与既有变体同形。`UnknownSession` 与 `UnknownNode` 由 06.3 提供，本批不动。`lib.rs` 声明 `pub mod commit` 与 `mod heads`，`pub use commit::{CommittedFrame, FrameBodyError, decode_frame, encode_frame}`，`heads` 的函数是 `pub(crate)`，不对外导出，与"操作级接口"的存储层纪律一致。`commit_frame` 取 `&mut self`、走 `self.conn_mut().transaction()`，与 `create_workspace`、`append_event` 的形状一致，不在同一句柄上留下两种事务获取方式。

## 已知缺口（非 06.4 缺陷，属计划明示留待后续批次）

- `nodes.body_kind` 是裸 TEXT，没有取值域 CHECK，`'frame'` 是 06.4 引入的第一个节点正文种类值，完整词表留给后续批次统一补，与 06.3 的 `kind` 词表问题同型。
- 事件表"不可变"仍是代码纪律，表结构层面无 `BEFORE UPDATE`/`BEFORE DELETE` 触发器，`events.id` 无唯一索引，06.3 已裁决本批不做。
- `decode_frame` 对摘要与指纹的字节切片按长度取，若喂入的不是 `encode_frame` 产出的合法正文（例如手工改库），字节偏移可能落在多字节字符中间而 panic 而非返回 `FrameBodyError`；合法前缀不会触发，因为偏移是原编码的字符边界。这是读路径的健壮性边界，不是本批的契约违背，读路径（08.x 的 `resolve` 输入组装）落地时再考虑要不要把切片换成 `get` 加错误返回。
