# Review R_06_9

Status: ok

## Conclusion

06.9 的标记清除 GC 正确实现了全局标记-清除加宽限期，不是引用计数。标记集是三张表（snapshot_entries.hash、nodes.body_hash、events.payload_hash）加 extra_roots 参数的并集，由 marks::collect 收集，租约根真被消费进标记集而非只透传。宽限期是两观协议：第一次观察只写 unreferenced_since 不删，第二次观察且超宽限期才删，写入与超期判断都在同一事务边界内（sweep_in 内），行删除在事务内、文件删除在提交后。删除顺序行先行文件随后，中断只留无引用文件（安全），不留下指向空内容的行（危险）。孤儿文件清扫（无 blob 行的文件含 .tmp）是回收的一部分。GC 删文件与回滚写回、squash 折叠之间不互相踩踏：回滚只读 CAS（cas::get_in）写工作区路径从不写 CAS 文件，squash 删增量条目但折叠后的有效状态仍被新基线条目引用，两者都是单写者顺序操作无并发。宽限期不重启不是缺陷：ADR 0018 把宽限期绑在在途工具生命周期上，靠租约表（extra_roots）保护，不是靠宽限期重启。十条验收全过，395 项测试全绿。

## Findings

- 标记集收集正确：marks::collect 从 snapshot_entries.hash、nodes.body_hash、events.payload_hash 三张表收集非空哈希，再并入 extra_roots 参数。节点不可变、事件 append-only，两者都是永久标记根，漏标即数据损坏。content_stored = 0 的哈希不在 blobs 里，标记它无害。
- 两观协议事务边界正确：sweep_in 在事务内完成标记、两观协议、删行，unreferenced_since 的写入与超期判断都在同一事务内。db::gc 提交后才调 sweep_files 删文件。中断只留无引用文件。
- extra_roots 真被消费：marks::collect 把 extra_roots 里的每个哈希 insert 进 HashSet，不是只透传。租约表还没建（09.x 执行器的职责），由调用方从租约表读出后传入，存储层不解析租约表，与 06.8 的"范围是参数"同型。
- GC 与回滚对齐不踩踏：align_in 只读 CAS（cas::get_in）写工作区路径，从不写 CAS 文件。它只读被 snapshot_entries 引用的 blob（有行），GC 不会删。GC 删行后文件还在（行先行文件随后），回滚查 blobs::exists 发现行没了就标 MissingContent 不读文件，不会崩溃。
- GC 与 squash 折叠不踩踏：rebaseline_in 删增量条目、重写基线条目，折叠后的有效状态仍被新基线条目引用，GC 不会误删。squash 与 GC 都是单写者顺序操作，无并发，任一顺序都安全。
- 宽限期不重启不是缺陷：ADR 0018 第 110 行把宽限期绑在在途工具生命周期上，靠租约表（extra_roots）保护。blob 被活跃租约持有时在 extra_roots 里被标记不删；租约释放后 blob 变无引用，宽限期从第一次观察起算。不需要在被引用后重启宽限期。
- 写入路径与 GC 孤儿清扫一致：put_in 文件先行行随后，sweep_orphans 删无行的文件含 .tmp。两者都是单写者顺序操作，无并发竞争。写入中断留 .tmp 或无行文件，GC 孤儿清扫清掉。
- 孤儿文件清扫正确：sweep_orphans 扫 CAS 目录，删没有 blob 行的文件（含 .tmp）。没有行的文件是无引用对象，删掉只省空间不丢内容。
