# 上下文节点类型审查

提交 `1a5c49f` 新增 `context` 模块。名义类型确实拦住了 id 互相误用，`8`、`9` 也已正确放行；但 `NodeBody` 缺消息方向与内容寻址句柄、分叉的父边语义未写明、固定层指纹没有消费点，三处会让 04.2 与 04.4 无据可依。

- 名义类型（`crates/ita-kernel/src/context/ids.rs:47` 至 `:94`）：每个名字生成独立元组结构体，字段私有且无 `From<String>`，`fn f(NodeId)` 不接受 `SessionId`，`Vec<NodeId>` 与 `Vec<SessionId>` 也不互通；唯一绕过是取 `as_str()` 再 `parse`，属显式行为。
- 字符集（`ids.rs:98`）：`A..=H`、`J`、`K`、`M`、`N`、`P..=T`、`V..=Z` 共 22 个字母，排除 `I/L/O/U`，`8`、`9` 走 `is_ascii_digit` 通过，实现正确。两处仍不严：ULID 首位只能是 `0` 至 `7`（48 位时间戳加 80 位随机恰好 128 位），当前允许首位到 `Z`，可构造任何生成器都不会产生的文本；回归测试（`:149`）只替换末位四个字母，从未断言 `8`、`9` 通过，也未穷举字母表。长度比较（`:64`）用字节数，25 个字符加一个多字节字符会报"实际为 26"。
- 分叉与父边（`node.rs:76` 至 `:78`）：父边指向另一会话的节点在结构上可表达，这正是共享祖先所需；注释只说"节点不复制"，未写父边可跨会话、`session` 指创建会话，04.2 若按会话过滤父链会静默丢掉祖先。
- `NodeBody`（`node.rs:13` 至 `:38`）：0003 四段中"当前待办"没有独立变体，只能塞进 `Notice` 或 `Turn`。`Turn`（`:20`）只有 `text`，没有 user/assistant 方向与轮次边界，而 04.4 要按方向拼数组、要数最近三轮；`ToolCall`（`:25`）把调用与结果压成一个节点，原生工具调用需要两条消息；工具结果（`:28` 至 `:29`）只有预览、无内容寻址句柄，无法还原完整结果，与"大对象外置"冲突。
- `covers` 与顺序（`node.rs:46`、`:65` 至 `:67`）：注释假设"解析时只调用一次"，但调用者要到 04.4 才出现，目前无代码约束；若逐节点查询，代价是链长乘覆盖长度，可能撞上 0018 的二十毫秒审视阈值。`covers` 只声明"按时间顺序"，无构造器校验顺序与去重，`PartialEq` 依赖录入顺序。
- 固定层指纹（`node.rs:49` 至 `:53`）：注释已说明是生成摘要时刻的指纹而非当前值，语义无歧义；但 0018 第一节的 `ResolveInput` 不含它，漂移表只有两个布尔量，格式未定义，且与 `FixedLayer.fingerprint` 是同一事实的两份拷贝，无人消费则撑不起逐字节复现。
- 注释与测试（`crates/ita-kernel/src/lib.rs:12`、`node.rs:130` 至 `:135`）：`missing_docs` 确实逼出了同义反复的注释，但它是下限，规范的全句写法仍可满足，不构成关闭理由；那条"帧可引用已不存在的检查点"赋值后立即断言自己刚赋的值，不验证弱引用，属占位。

## 问题

1. `ids.rs:98` 首位加一条 `0..=7` 的取值限制，`:149` 补穷举用例，固化 `0` 至 `9` 与除 `I/L/O/U` 外全部字母被接受。
2. `node.rs:20` 给 `Turn` 补方向与轮次边界，或写明方向由 `ResolveInput.recent` 承载；`node.rs:25` 明确 `ToolCall` 由一个节点展开为两条消息。
3. `node.rs:29` 补内容寻址句柄（哈希与长度）；`node.rs:13` 补"当前待办"变体。
4. `node.rs:77` 写明父边可跨会话、`session` 是创建会话；`node.rs:46` 写明 `covers` 是有序序列并由 04.4 的调用方式约束开销。
5. `node.rs:49` 的指纹或删除，或写明比较方与不相等时的注入措辞。
