# heredoc 状态机审查

Status: issues

## 结论

十项失败在提交 `8ae3933` 里都有检测与断言，空正文被接受，正文按字节原样返回，无截断交付路径。阻断项两条：`TrailingText` 偏移漏加分隔符长度且与 `InvalidDelimiter` 基准不一；未引号检查漏了反斜杠引用与续行，正文含 `\` 时与 bash 交付的字节不同。

## 逐项

- 覆盖：未终止（`crates/ita-kernel/src/command/heredoc.rs:77`）、残留（`:90`）、超 1 MiB（`:82`）、非法分隔符（`:148`）、CRLF（`:271`）、行尾空格（`:265`）、空正文（`:245`）、未引号含展开字符（`:99`）在 heredoc.rs；`<<-`（`crates/ita-kernel/src/command/lex.rs:84`）与 `<<<`（`lex.rs:77`）在词法层，各有断言，无遗漏。
- 残留偏移（`heredoc.rs:92`）：三个分量相对 `after_delimiter`，漏加 `base_offset` 与 `consumed`。用例 `:225` 里残留首字节在 `rest` 第 23 位，实际报 14；`InvalidDelimiter`（`:136`）用 `rest` 基准，函数文档（`:26` 至 `:44`）又没写基准，两套坐标并存。测试 `:227` 只匹配变体，测试集无法发现数值错。
- 未引号漏反斜杠（`heredoc.rs:99`）：bash 在未引号 heredoc 里用 `\` 引用 `\`、`$`、反引号并吞掉 `\` 接换行；正文 `a\\b` 在 bash 交付 `a\b`，这里交付原样四字节，与 0018 第八节冲突。`:202` 与 `:208` 只覆盖 `$`，判不出。只该拦这四种组合，其余反斜杠 bash 也按字面保留，全拦会误伤。
- 是否过严：拒绝含 `$` 的正文是 0007 第 24 行明文要求，不是实现者加码；含 `$` 的脚本改用 `<<'EOF'` 一次往返即可改对，放行则 `$HOME` 静默变字面量。规则保留。
- 分隔符同行余文（`heredoc.rs:48` 至 `:56`）：`<<'EOF' > out` 里 ` > out` 既不报错也不返回，签名也不带消费长度，03.4 只能自己再算正文起点，直接依赖本函数就会静默丢。接口缺口，需在装配前定死。
- 字符集与长度（`heredoc.rs:156` 至 `:175`）：字母数字下划线连字符加 64 字节是 0007 之外的新增收窄，`<<'END.MARK'` 会被拒；收窄可接受，但 `MAX_DELIMITER_LEN` 不在 0018 第九节参数表里，与"全部参数都要有配置入口"不符。
- 残留判定（`heredoc.rs:90`）：`!c.is_whitespace()` 只放过纯空白，终止行之后的空行与缩进行不误判，"正文之后又写一条命令"会被拦下；副作用是正文撞上分隔符且其后只剩空白时静默截短，这是 0007 第 75 行认下的代价，建议补用例固定。
- 正文含 `$` 的偏移（`heredoc.rs:100`）：传 0，既非分隔符位置也非正文起点；`error.rs:139` 的提示以"分隔符不合规则（…）建议使用形如 `ITA_EOF`"开头，对"该加引号"这条真建议是误导。
- 其余：`<<` 后直接换行得到空分隔符并报 `InvalidDelimiter`，与 `error.rs:40` 的 `MissingTarget` 注释重叠，分工需统一；CRLF 与行尾空格报未终止与 bash 一致，提示不够准，但变体在 03.1 已冻结。

## 问题

1. `TrailingText` 偏移补 `base_offset` 与 `consumed`，把 `scan_heredoc` 偏移基准统一为 `rest` 写进文档，补一条断言具体数值的用例。
2. 未引号检查补 `\` 接 `\`、`$`、反引号与换行四种组合，其余反斜杠放行。
3. 明确分隔符同行余文的归属：返回消费长度由装配层续接，或在此处报错。
4. 正文含展开字符改用不带位置的错误或报正文起点；定下 `MissingTarget` 与 `InvalidDelimiter` 在空分隔符上的分工。
5. 64 字节上限要么删除，要么登记进 0018 第九节参数表并搬进配置结构。
