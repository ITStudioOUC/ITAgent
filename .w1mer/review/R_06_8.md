# Review R_06_8

Status: ok

## Conclusion

06.8 的回滚对齐实现正确，十条验收全部成立。核心是独立动词 `Store::align(scope, target, range, force)`，不折进 `create_snapshot`，与 06.6 的链追加、06.7 的 squash 链改写是第三种独立职责。回滚目标沿链从基线折叠到目标（含目标），折叠算法提取为共享模块 `fold`，与 06.7 squash 共用同一套左结合覆盖加墓碑删除，提取忠实（逐行比对旧 `squash::fold` 与新 `fold::fold` 体一致，三条单测原样迁到 `fold.rs`）。范围是参数、存储层不解析工具清单，范围外路径不碰只进残留清单。四种情况全处理：写回（磁盘无则从 CAS 写回）、覆盖（磁盘有且哈希与目标不一致则默认拒绝、force 覆盖）、墓碑删除（折叠后不含墓碑，范围内新建删除走独立循环）、超阈值条目（`content_stored = 0`）只报告从不删除不覆盖。写回前核对 `blobs` 行，缺失标注"内容缺失"不写回。外部改动检测是"磁盘与目标哈希不一致"，默认拒绝除非显式强制。十条验收各写成一条集成测试且通过。`ResidualReason::BackgroundLeftover` 在枚举里有名字但 `align_in` 尚未填充，是已知缺口非缺陷。

## Findings

- 核心逻辑正确：`align_in` 先读目标快照 seq 并校验属本工作区（跨工作区返回 `UnknownSnapshot`），再读所有 `seq <= target_seq` 的快照按 seq 升序折叠得有效状态，对有效状态每条按四种情况处理，再对范围内磁盘存在但不在有效状态的路径删除。折叠结果不含墓碑，`Tombstone` 分支是防御性 `unreachable!`。
- 共享折叠提取忠实：`fold::fold` 与旧 `squash::fold` 体逐行一致，`squash.rs` 与 `retention.rs` 都改为调用 `fold::fold`，三条单测原样迁移到 `fold.rs`，无行为变化。
- 独立动词成立：`Store::align` 开立即事务、调 `align::align_in`、提交，`create_snapshot` 未改动，对齐不折进快照创建。
- 范围是参数：`align_in` 收 `range: &[String]`，存储层不解析工具清单；范围外文件与目录进 `OutOfRange` 残留，不碰。
- 写回前核对 blobs：`content_stored = true` 的条目先 `blobs::exists`，缺失标 `MissingContent` 不写回；超阈值条目（`content_stored = false`）标 `Oversized` 只报告，从 `cas::get_in` 之外的路径读不到内容也不写回。
- 外部改动检测：磁盘有且哈希与目标不一致时，`force = false` 返回 `AlignRefusedExternal`、磁盘不变，`force = true` 从 CAS 覆盖。
- 事务纪律：`align` 开立即事务，`align_in` 失败时事务回滚不提交，`cas_root` 先克隆避免与可变连接借用冲突，与 `put` 同型。
- 十条验收测试齐全：`align_deletes_newly_created_in_range`、`align_reports_oversized_without_deleting_or_overwriting`、`align_does_not_touch_out_of_range_and_reports`、`align_checks_blobs_before_write_back`、`align_marks_missing_content_in_residual_list`、`align_refuses_external_change_by_default`、`align_overwrites_external_change_when_forced`、`align_folds_chain_from_baseline_to_target`、`align_rejects_cross_workspace`、`align_allows_empty_effective_state`，各守一条验收。
- 已知缺口非缺陷：`ResidualReason::BackgroundLeftover` 在枚举里有名字与描述，但 `align_in` 尚未填充（快照之后新建、不在范围内的后台遗留），本批十条验收不测它，留待后续批次。
- 非阻塞观察一（死代码）：`StoreError::AlignRootMissing` 在 `db.rs` 声明并有 `Display`，但全树无构造点。`align_in` 从 `workspaces` 表读 `root_path` 后不检查磁盘存在性，根路径缺失时 `create_dir_all`/`write_back` 会懒创建，该变体不可达。建议删掉或在读根路径后补存在性检查。
- 非阻塞观察二（文档与行为不符）：`restore.rs` 模块头写"删除是递归删除，目录与文件都处理"，但 `delete` 用 `remove_file`，对目录路径返回 `Cas` 错误而非递归删除。范围内新建删除的验收只覆盖文件，目录情形未测。文档要么改成"只删文件"，要么实现递归删除。
- 非阻塞观察三（注释纪律）：`align.rs` 模块头出现 ROADMAP 编号（06.6/06.7/06.8）与 ADR 编号（0017/0018），违反 `COMMENT_GUIDELINES.md` 第一节"禁止内部编号"。ROADMAP 编号模式在 `squash.rs` 模块头是 06.7 引入的既有写法，ADR 编号模式在 `db.rs`/`retention.rs` 是既有写法，本批 `align.rs` 沿用了既有模式但新增了两处命中。既有命中不在本批范围内，不写入归档。
