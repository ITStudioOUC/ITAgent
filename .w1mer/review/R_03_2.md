# 词法扫描审查

Status: issues

## 结论

提交 `267b2d4` 新增了纯函数 `scan` 与 `Token`、`TokenKind`，无 IO、无全局状态，算符判定与词内终止的行为在 `a|b` 和 `a | b` 两种写法下一致，单引号内不解释替换也与真实 bash 相符。阻断项有两处：双引号内的转义自行发明了一套规则，与 bash 不同且已被测试固定，0007 第 66 行的可粘贴承诺因此失真；通配符只拒了 `*` 与 `?`，`[`、`{`、`}`、变量引用与波浪号全部按字面通过，粘贴到 bash 会指向不同文件。次要项是行中单个 `\r` 会静默丢弃余下命令，以及两处注释与实现相反。

## 逐项

- 双引号转义（`crates/ita-kernel/src/command/lex.rs:213` 至 `:221`）：`\n` `\t` `\r` 被换成控制字符，其余 `\x` 一律去掉反斜杠，于是 `"\n"` 在 ita 里是换行、在 bash 里是反斜杠加字母 n 两个字节；`"\$"`、`"\\"`、`"\""` 恰好一致，`"\'"` 与 `"\a"` 不一致。这段规则正是 bash 的 `$'...'` ANSI-C 语义，而 `$'a\nb'` 在 `lex.rs:171` 又被当作单引号字面，两个方向都偏。测试 `lex.rs:292` 至 `:301` 断言 `"a\nb"` 得到换行，把分叉写成了预期。
- 单引号（`lex.rs:171` 至 `:183`）：正文按字节原样拷贝，反引号与 `$(` 在单引号内放行，与 bash 一致，因此不存在误伤合法文档的问题；唯一问题是注释 `lex.rs:51` 至 `:52` 声称"任何位置都拒绝"，与实现相反，会诱导 heredoc 与装配层照抄这条从严策略。
- 管道（`lex.rs:124`、`:162`）：`|` 在词内先终止词，回到主循环再报同一变体，`a|b` 与 `a | b` 除偏移数值外完全等价，无问题。`;`、`&`、反引号同理，行为一致。
- 通配符（`lex.rs:131`、`:163`）：只拒 `*` 与 `?`。`[ab].txt` 在 bash 是字符类通配、`{a,b}` 是花括号展开，两者在这里都当字面路径，粘贴执行会写到另一个文件，与 0007 第 14 行"通配符没有例外"冲突。同类静默分叉还有 `$VAR`、`${VAR}`（`lex.rs:117` 只拦 `$(`）与 `~`：ita 当字面，bash 展开成变量值或家目录。
- 位置（`lex.rs:179`、`:189`、`:136`）：未闭合引号报引号起点，比报词起点更准，可接受；但测试 `lex.rs:394` 至 `:397` 的输入里词起点与引号起点都是 9，无法区分两者，换成 `ita a'b` 才有判据。偏移是字节数（`lex.rs:31` 已写明），多字节路径下模型按字符数会偏；`Display` 仍不带偏移，03.1 提出的那条至今没有承接。
- 测试（`lex.rs:247` 至 `:411`）：缺 CRLF、行尾反斜杠、UTF-8 多字节、空引号 `""`、相邻引号拼一个词（`a"b c"d`）、`\\` 与 `\$` 的用例。另有一处未覆盖的行为：`\r` 在 `lex.rs:62` 与 `:160` 被当终止符，`ita a\rb` 会静默丢掉 `b`，而 bash 里 `\r` 是普通字符；既不等于 CRLF 容错，也不等于拒绝，是最难排查的一类静默差异。

## 问题

1. 双引号转义改为 bash 语义（只处理 `\$`、`` \` ``、`\"`、`\\` 与续行），或对不支持的转义显式拒绝并提示改写；同步改掉 `lex.rs:292` 的断言。
2. `[`、`{`、`}`、`$` 变量引用与 `~` 要么拒绝，要么在文档里明写"按字面处理、与 bash 不同"，不能沉默通过。
3. `\r` 只在行尾且与 `\n` 相邻时当终止，行中单个 `\r` 按字面或拒绝，禁止静默丢弃余下命令。
4. `lex.rs:40` 的"双引号内保留字面"与 `lex.rs:51` 至 `:52` 的"任何位置"改到与实现一致。
5. 补 CRLF、行尾反斜杠、UTF-8、`""`、相邻引号与未闭合位置的用例。
