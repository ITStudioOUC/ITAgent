# 失败矩阵审查

提交 `325da8d` 新增 `crates/ita-kernel/tests/command_matrix.rs`，在公共 `parse()` 上跑三十二条失败用例与十二条合法用例，错误类别、提示关键词与是否可重试三项都有断言，测试之间没有共享状态。两处实质缺口：ROADMAP 要求的 CRLF 一项在矩阵里没有任何用例，合法表漏掉 ADR 0007 明示接受的 `<<"X"` 与未加引号的干净正文。另有提示断言偏松：`<<`、`&`、`分隔符`、`无法解析的文本` 四个关键词对同类型错误恒真，类别对而提示没用时仍会通过。

## 逐项

- 十项覆盖（`crates/ita-kernel/tests/command_matrix.rs:146` 至 `:215`）：未终止、碰撞、残留、超上限（`:273`）、非法分隔符、`<<-`、`<<<`、行尾空格都有用例；空正文只在合法表 `:296` 用 `is_ok` 通过，没有断言正文为空。CRLF 一条缺席，`crates/ita-kernel/src/command/heredoc.rs:285` 只覆盖了模块内部，公共入口层没有断言，而 03.5 的验收口径正是"公共入口覆盖全部拒绝路径"。
- 提示强度（`:110` 至 `:119`、`:62` 至 `:65`、`:182` 至 `:185`、`:164` 至 `:167`）：herestring 只查 `<<`，`<<-` 的提示同样含 `<<`，两条可互相顶替；后台执行只查 `&`，与 `&&` 无法区分；"非法分隔符字符"只查 `分隔符`，而 `crates/ita-kernel/src/command/error.rs:146` 对全部 `InvalidDelimiter` 都带这个词；残留三类只查 `无法解析的文本`，该句对所有 `TrailingText` 相同，不验证残留片段是否回显。`matches` 闭包（`:40`、`:52`）不校验 `UnsupportedOperator` 的 `text`，算符认错也能通过。
- 合法表（`:284` 至 `:297`）：含 `$` 与反引号的单引号正文、空参数、等号参数都在，正是最容易被规则误伤的三种写法。缺 `<<"X"` 与未加引号的干净正文 `<<X\nplain\nX`，ADR 0007 第 23 至 24 行对两者都是接受，而 `heredoc.rs:211`、`:216` 只在模块内部测过。
- 失败定位（`:221` 至 `:247`）：主表汇总后统一断言，消息带用例名、实际错误与提示，但只把输入写进"应当被拒却成功"一条，多行 heredoc 用例只能靠中文用例名回查。第二条测试（`:250`）循环内直接断言，首条失败即中止，且 `let Err(..) else { continue }` 在那条测试里静默跳过可解析的用例；它只要求 `offset()` 非空，偏移算错不会被发现。
- 并行稳定性（`:23`、`:224`、`:251`）：`cases()` 每次重新构造，`parse` 是纯函数，没有全局状态与文件写入，nextest 下互不影响。
- 结论：骨架正确，缺口集中在 CRLF 与两条 ADR 明示接受的写法，提示断言需收紧到能区分同类型错误的程度。

## 问题

1. `command_matrix.rs:146` 后补 CRLF 用例（终止行为 `X\r`，期望 `UnterminatedHereDoc`），合法表补一条正文含 `\r\n` 的用例。
2. `command_matrix.rs:296` 前补 `ita edit <<"X"\nbody\nX` 与 `ita edit <<X\nplain\nX`。
3. `command_matrix.rs:113`、`:65` 把关键词收紧为 `<<<`、`herestring`、`&&` 这类可区分的词；`matches` 对 `UnsupportedOperator` 同时断言 `text`；`:296` 的 `is_ok` 改为断言正文为空。
4. `command_matrix.rs:233` 起在失败消息与第二条测试里带上输入，并对残留用例断言具体偏移。
