# 工具正文瘦身审查

瘦身函数保持纯函数、可复现，空输出、多行与无正文三种边界都有用例；但委托给该函数的三样东西里"命令"在结构与入参中根本不存在，且一行结果没有长度上限、首行为空时会误报"无输出"，按 0004 与验收口径判 `issues`。

1. 命令缺失（`recent.rs:4` 至 `:5`、`:15` 至 `:24`、`:55`）。模块文档称只留"命令、一行结果、节点编号"三样，而结构与入参都只有结果节点，拿不到 `ToolCall` 的 `command`；命令只能靠消息数组里相邻的调用消息推断，0004 第 43 行要求的"命令 + 一行结果 + 编号"在同一条消息里不成立。
2. 一行结果没有长度上限（`recent.rs:60` 至 `:61`）。预览头本身是 4 KiB，输出若是一条无换行的长行（压缩后的 JSON、进度条），`line` 会接近整段预览，瘦身一点预算也省不下；应截到固定字符数并在截断处保留节点编号。
3. 首行为空但后面有内容时误报无输出（`recent.rs:60` 至 `:61`）。`lines().next()` 取到空行就落到占位，退出码非零而报错在第二行时，模型会读到"（无输出）[退出码 2]"这种自相矛盾的摘要；占位应只在整段预览为空或全空白时使用。
4. 非零退出码的错误信息没有覆盖（`recent.rs:147` 至 `:155`）。唯一带非零退出码的用例预览正文是 `ok`，只断言了退出码与编号出现，没有断言报错文本仍留在 `line` 里。
5. 按号取回的操作没有承载点（`recent.rs:7`、`:73` 至 `:74`）。渲染文案承诺"完整输出见节点"，但内核无取回工具，仓库里也没有写明由哪个命令接收这个编号，"内核给编号、执行器负责取回"只存在于注释语气里，没有契约位置。
6. `slim_all` 跳过非工具节点（`recent.rs:84` 至 `:86`）不算错位：结果自带节点 id，调用方按 id 而不是位置对齐，且当前唯一失败情形正是"不是工具结果"；只需注明 `filter_map` 只允许吞 `NotAToolResult`，将来加错误变体时必须改回传播。

需要复核的信号：若后续把瘦身结果直接替换 `recent` 里的结果节点，命令是否还在上下文里取决于 `ToolCall` 是否一并保留；任何一条丢弃调用节点的路径都会让第 1 条退化成"有结果无命令"。

## 处置记录

| 问题 | 处置 |
|---|---|
| 瘦身结果缺"命令"，模型不知道结果对应哪次调用 | 加 `command: Option<String>`，由调用方按会话结构配对（内核不维护调用-结果映射）；渲染时输出 `$ 命令` 前缀，缺命令时标注未知 |
| 取预览首行但不截断，4 KiB 无换行输出省不下预算 | 加 `LINE_LIMIT`（512 字节）并按字符边界截断，避免切开多字节字符；补超长单行与多字节两例 |
| 首行为空时误报"（无输出）" | 改为取第一条非空行 |
| 缺非零退出码用例 | 补 `cargo build` 失败、`error[E0308]` 保留在 line 中的用例 |
| 只在文案里承诺"按号取回"，没有接收方契约 | 编号由执行器在 `recall` 类工具里消费，属 09/11 的范围；此处只保证编号可读且稳定 |
| `resolve.rs` 仍把整段预览拼进消息，与瘦身并存会重复占预算 | 解析侧同步改为只取第一条非空行 |
| `slim_all` 静默跳过非工具节点 | 注释写明它只吞 `NotAToolResult`，将来新增变体必须显式匹配 |
