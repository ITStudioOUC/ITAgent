# 内核纯净门补审

Status: ok（四处缺口已在同一子批次内关闭）。主体成立：crate 内配置只约束内核，两条 deny 让命中即失败，脚本的零依赖断言
与 build.rs 检查各自独立，版本 0.1.1 与提交信息合规。以下四处缺口不否定主链路，但都能在没有
恶意的日常编码里让 IO 或时钟混进内核。审查对象 4098ae4，基线 db117e9。

## 问题

1. dev-dependency 豁免与 AGENTS.md 口径不一致。现象：`[dev-dependencies]` 加 tokio、测试里写
   `tokio::time::sleep`，三个判据全过。根因：`check_kernel_purity.sh:21` 排除 dev 依赖，
   `crates/ita-kernel/clippy.toml` 只列 std 路径，两处豁免叠成无检通道；AGENTS.md:46 写的是含
   dev 的 `cargo tree -p ita-kernel`，`18_plan-02-2.md:228` 只把它当成"rand 可进测试"。
   建议：对 dev 依赖做白名单断言并同步 AGENTS 措辞；若长期豁免，就在文档写明"纯度只约束产物"。
2. build.rs 检查可被清单字段绕过。现象：`crates/ita-kernel/Cargo.toml` 写 `build = "src/gen.rs"`，
   脚本仍通过，gen.rs 里的 `std::fs` 不受任何检查。根因：`check_kernel_purity.sh:15` 只判固定
   路径，cargo tree 只画依赖，clippy 不 lint 构建脚本。建议：用 `cargo metadata --no-deps` 断言
   无 custom-build target，或先 grep `Cargo.toml` 的 `^build` 键。
3. 漏掉的 std 入口。现象：`std::process::id`、`std::thread::current`、`std::thread::available_parallelism`、
   `std::io::copy`、`std::io::read_to_string`、`std::fs::exists`、
   `std::collections::hash_map::RandomState::new`、`std::backtrace::Backtrace::capture` 都不触发。
   根因：`clippy.toml` 是手写枚举，`18_plan-02-2.md:225` 承认新 API 会漏但未列这批已稳定入口；
   `disallowed_types` 只匹配源码写出的路径，`thread::current()` 的返回类型是推断的，抓不到。
   建议：补进 `disallowed-methods`（`RandomState` 进类型表），02.3 用探针逐条验证。
4. `crates/ita-kernel/clippy.toml:6` 到 `:7` 的兜底说明与实测不符（低）。现象：注释称无效条目会
   "配合 `-D warnings` 直接失败"，实测该诊断不走 lint 通道、`-D warnings` 不升级、退出码仍为 0
   （`18_plan-02-2.md:201`），真正兜底的是 `check_kernel_purity.sh:33` 的 grep。根因：注释写的
   是预期而非实测。建议：改为"由纯净门脚本的 grep 兜底"，免得后人以为裸跑 clippy 就够。

## 已核对无问题

- 版本 `Cargo.toml:6` 为 0.1.1：02.2 是 0.1.0 基线后的第一个批次，一次推进，符合第 4 节。
- 提交信息 `feat: 加内核纯净门，禁止时钟与 IO 并断言零依赖`：type 合法，无 scope、任务号、哈希、
  测试计数与分隔符，主题 22 字，写的是改了什么而非实现步骤。
- 两条 clippy deny 与 `deny(missing_docs)` 不冲突，分属 clippy 与 rustc 两套 lint，`cargo build`
  仍通过；`std::fs::File::open` 由类型条目拦住，类型与方法条目互补成立。
