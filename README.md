# ITAgent

爱特工作室自主开发的长程自主开发跨平台 Agent。

构建出的二进制叫 `ita`。设计原则是**克制的内核与自由的用户态分离**：内核只做纯逻辑，
一切 IO、进程、沙箱与模型调用都在内核之外。这条分离不是风格偏好，而是被编译器与进程边界
共同强制的架构约束，因此系统的每个部分都可以独立替换、独立测试、独立崩溃。

当前状态：架构决策已定（见 [`docs/adr/`](docs/adr/)），代码尚未开始。开发路线见
[`.w1mer/ROADMAP.md`](.w1mer/ROADMAP.md)。

## 它想解决什么

长程自主开发里最实际的三个障碍，分别对应三组设计：

**上下文会爆，注意力会衰减。** 待办做完之后，过程中的试错细节不再需要占据预算，但成果
必须保留。因此提供一层上下文回退：回到开启待办的位置，注入一条摘要，文件完全不动。
上下文与文件是两条独立的时间轴，可以自由组合。

**试错改坏了工作区。** 每次有改动的工具调用之后自动留一份文件快照。用户和 agent 共用同
一个回滚工具，因此 agent 可以在试错之后自己退回，不需要人来收拾。

**多个工作区并发时互相污染。** 一个 server 管全局路由、数据库与凭据，每个工作区一个
worker 进程加一个执行器。worker 无状态、无数据库连接、无密钥、默认无网络——崩溃即重建。

## 架构

```
                      ┌─────────────────────────────┐
   ita (CLI/TUI) ────►│  server                     │
                      │  · 唯一数据库写者（SQLite）  │
                      │  · 模型代理（凭据只在这里）  │
                      │  · unit 监督（依赖拓扑）     │
                      └──────────┬──────────────────┘
                                 │ 本地 IPC
                      ┌──────────▼──────────────────┐
                      │  worker（每工作区一个）       │
                      │  · 无状态、无数据库、无密钥   │
                      └──────────┬──────────────────┘
                                 │
                      ┌──────────▼──────────────────┐
                      │  执行器（每工作区一个）       │
                      │  · 权限预检 · 租约 · 快照     │
                      └──────────┬──────────────────┘
                                 │
                      ┌──────────▼──────────────────┐
                      │  沙箱 → 工具模板 → 二进制     │
                      └─────────────────────────────┘
```

**代码分层**：`ita-kernel` 只放纯逻辑（消息树与解析、命令文法、租约与权限谓词、检查点
类型），不得依赖任何带 IO 或时钟的 crate。存储、协议、沙箱、执行器、模型适配、工作流都在
内核之外。CI 会用依赖检查守住这条线，因为靠约定守不住。

## 几个值得单独说的决定

**工具调用是命令行，不是结构化参数。** 模型只看到一条 `command` 字符串，文法是受限的
bash：参数、管道、重定向、heredoc。因此命令可以直接粘贴到真实终端里复现，权限也能对整条
管道做执行前预检。heredoc 属于词法层而不是编辑工具，因为"给命令提供标准输入"是通用能力。

**只用原生工具调用。** 不做正文标签解析，也不做正文 JSON。工具定义只有一项且永久静态，
新增工具靠追加目录事件，这样供应商的前缀缓存不会失效。检索结果进消息而不进工具定义，
原因相同。

**工具是"清单 + 模板 + 二进制"。** 清单声明权限（文件范围、网络意图等），模板是固定的
回调 ABI，负责把请求交回执行器、拿到租约后再执行真正的二进制。首次安装需要人工批准，
批准绑定内容哈希；升级只批准新增的权限。

**回滚保证的边界是明确的。** 只保证工作区内、被工具声明范围内修改过的文件。构建产物、
工作区外的写入、网络副作用不在保证范围内，回滚结束后会打印"可能残留"清单。宁可说清
边界，也不让"回滚"这个词承担它做不到的承诺。

**成本纪律。** 不做付费评测。只做本地零成本测量（文法吞吐、解析耗时、数据库单写吞吐、
进程间往返、快照耗时、冷启动分解），加上供应商免费回传的用量字段。

## 开发

```sh
git clone <repo> && cd ITAgent
.w1mer/scripts/install_hooks.sh    # 装提交信息校验与提交前格式化钩子
w1mer list                         # 看当前该做什么
```

日常验证三件套：`cargo nextest run -p <crate>`、`cargo build --workspace`、
`cargo clippy --workspace --all-targets`。

开发由 W1MER 协议推进（三并调度：reviewer、implementer、explorer），规划目录
`.w1mer/` 随仓库提交，是跨批次的事实来源。
